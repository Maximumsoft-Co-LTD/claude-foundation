## Critical

### C1. Any provider receipt can be forged with one flag → `PROVEN` with nothing executed
`.claude/harness/runtime/evidence/receipt-runtime.mjs:126` (gate), `:87` (adapter is caller-supplied)

The real-evidence requirements (`observed`, `provenance.source`, one artifact or
reference) are gated on `adapter === "external"`. `adapter` comes from
`flags.adapter || config?.adapter || "external"` — so the caller chooses it.

```js
const adapter = flags.adapter || config?.adapter || "external";
...
if (adapter === "external" && status === "pass") { /* the only evidence checks */ }
```

`commandExecutionId` is stored but never validated anywhere. For an unconfigured
provider, `receiptValidity` recomputes the expected fingerprint from the
receipt's own `adapter`/`command`/`environment` fields, so a forged receipt
validates against itself.

**Reproduced end-to-end** on a clean install:

```
$ foundation receipt forge-probe test pass
BLOCKED: passing external receipt 'test' is missing:
  observed — ...   source — ...   artifact or reference — ...

$ foundation receipt forge-probe test pass --adapter command
RECEIPT forge-probe/test: pass          # accepted, zero evidence

$ # repeat for every required provider, then:
$ foundation proof-run forge-probe
EXECUTION proof-1786037545197: all receipts reused
PROVEN forge-probe
  providers: accessibility, compatibility, data-migration, discovery, test
  next: /land forge-probe
# runtime: status=proven, provenHash=4e22be6b...
```

Nothing was ever executed. Only `review` and `acceptance` resist, via their own
field requirements. `commands.json:34` classifies `evidence record` as
`kind: "authority"`, yet unlike every other authority command (`land record`,
`budget continue`, `change abandon`) it requires no `--decision-ref` and no
attestation.

**Impact**: the harness's core guarantee — that `PROVEN` means evidence ran — is
unenforced. This is the one to fix first.

### C2. Archive never re-projects an already-applied sandbox — proven code silently does not land
`.claude/harness/runtime/workflow/apply-runtime.mjs:480` (was 454) — **reproduced**

```js
if (["worktree", "copy"].includes(readiness.state.workspace?.mode) &&
    !readiness.state.workspace.applied) {
  applySandbox(id, { controlPlane: true });
```

Once `workspace.applied` is true, further sandbox work is proven, passes
`land check`, and archives as success while the target keeps the **first**
projection. `verifyAppliedProjection` cannot catch it — it compares the target
against the journal's recorded `after`, never against the current sandbox.

Trigger: archive fails after the apply step (the tests inject exactly this —
`run-harness-tests.sh:1112` asserts `applied` is retained "for archive retry").
Fix the code in the sandbox, re-run `/prove`, re-run `land archive`.

Reproduced: sandbox held `v2-critical-fix`, target ended at `v1-applied`,
`LAND READY -> ARCHIVED`, exit 0. `cleanupAppliedSandbox` then deletes the
sandbox and `cleanupApplyTransaction` deletes the backups — **the proven fix is
unrecoverable**. `applySandbox` already implements correct re-projection
(`buildReapplyEntries`, early return at `:292`); that path is reachable only
from `sandbox apply`, never from Land.

### C3. Recovered-archive path bypasses every Land guard
`.claude/harness/runtime/workflow/apply-runtime.mjs:445` (was 420) — **reproduced**

If `openspec/changes/<id>` is absent and any archive dir matching `<id>` or
`*-<id>` exists, `archive()` declares the change archived **before** `landCheck`
runs. Skipped: `assertNoDroppedScenarios`, proof freshness, per-provider
`receiptValidity`, receipt-manifest digest match, `verifyAppliedProjection`,
`assertMultiRepositoryArchiveReady`, `pendingTasks`.

Trigger: `openspec archive` moves the change directory then exits non-zero, or is
interrupted after the move. Recovery cannot distinguish "succeeded then crashed"
from "moved then failed".

Reproduced with a stale proof **and** an unchecked task:

```
$ foundation land check stale-demo
BLOCKED: proof is stale (be50c744 != 0649b2d5)
$ foundation land archive stale-demo
ARCHIVED stale-demo / recovered: interrupted archive transaction   # exit 0
```

Target still holds `before` — nothing was ever applied.

### C4. Unauthenticated remote crash: `GET //` kills the dashboard process
`dashboard/server.js:1186` — **reproduced**

```js
const url = new URL(req.url, `http://${req.headers.host || 'localhost'}`);
```

`new URL("//", base)` throws `ERR_INVALID_URL` synchronously inside the request
listener. There is no try/catch and **no `uncaughtException`/`unhandledRejection`
handler anywhere in the file** (verified: `grep -c` → 0). The process dies.

Trigger: `curl --path-as-is http://host//` — no key, no body. Also any Host
header the parser rejects (`Host: ]`).

`railway.json` sets `restartPolicyMaxRetries: 10`, so eleven requests turn a
restart loop into a permanent outage. Non-crashing `//` targets misroute instead:
`//api/online?key=…` parses to host `api`, path `/online` (verified), so a proxy
emitting a double slash silently breaks the API.

## High

### H1. Sandbox cleanup is a no-op for every non-applied change
`.claude/harness/runtime/workflow/apply-runtime.mjs:337` — **reproduced**
(found independently by two agents and the lead)

```js
const path = state.workspace?.sandboxPath;   // only ever set by a successful apply
if (!path || ... ) return { status: "not-needed", path: path || null };
```

`createCopy`/`createSingle` store the sandbox under `workspace.path`; only
`apply-runtime.mjs:311` writes `sandboxPath`. So for any never-applied sandbox
the function short-circuits and removes nothing, while the abandon record claims
`"workspaceCleanup":{"status":"not-needed","path":null}` — a false all-clear.

Reproduced: `sandbox create` → `change abandon` → sandbox still on disk.
**Measured on this machine: 739 leaked directories, 1.5 GB**, oldest 2026-08-03.

Second failure mode: multi-repo `sandbox create` rollback prints "created
sandboxes rolled back" but leaves the root worktree; runtime state resets to
`mode: "current"`, so retry bypasses the "sandbox already exists" guard and dies
on raw git output. No state references the leftover, so no command can clean it.

### H2. Orphaned zero-byte lease file deadlocks a resource permanently
`.claude/harness/runtime/workflow/lease-runtime.mjs:52-70` — **reproduced**

```js
const handle = openSync(path, "wx");
try { writeFileSync(handle, ...); } finally { closeSync(handle); }
acquired.push(path);
created.push(path);      // ← too late; a failed write is never rolled back
```

A 0-byte descriptor is immortal: `readJson(path, {})` yields `{}`, so
`Date.parse("") <= Date.now()` is `false` and the expiry branch never fires,
while every ownership-guarded delete requires `current.changeId === id`, which an
empty file can never satisfy.

Trigger: ENOSPC/EIO on the write, or Ctrl-C between `openSync` and
`writeFileSync` during `agents acquire`.

Consequence: `workspace:root` — the whole repository — becomes permanently
unleasable for **every** change:

```
FAIL: resource 'workspace:root' is leased by unknown/unknown
LEASE ABSENT chg/T001          # release --force deletes nothing
```

Recovery requires manually deleting a file under `.foundation/leases/resources/`
that no command or message names.

### H3. Recovered archive commits `archived` and destroys the sandbox before auditing the proof
`.claude/harness/runtime/workflow/apply-runtime.mjs:456` (was 431) — **reproduced**

`saveRuntime(initial)` (status archived) and `cleanupAppliedSandbox` run
**before** `proofAudit`. When the audit fails, the archived state and sandbox
deletion are already persisted. Every command then refuses, with no exit:

```
archive       -> BLOCKED: archived proof audit failed: missing-proof
land check    -> same
validate      -> BLOCKED: change is already archived
change abandon-> BLOCKED: change is archived; an archived change is already terminal
```

Exactly the dead-end class commit `6bcae63` set out to remove.

### H4. Sandbox work committed inside the sandbox is silently dropped from the projection
`.claude/harness/runtime/workflow/apply-runtime.mjs:60` — **reproduced**

`sandboxDiffNames`/`gitApplyInputs` build the projection from `git diff HEAD`, so
only **uncommitted** changes become apply entries. But the proof hashes the
sandbox git index (`state-runtime.mjs:193`, `git ls-files -s`), which includes
committed content, and `canonicalChangedSurface` (`packet-runtime.mjs:74`)
explicitly diffs `baseHead...HEAD` — the harness elsewhere assumes sandbox
commits exist. `build.md` says "never commit" but nothing enforces it.

Reproduced: sandbox committed `app.txt`, left `other.txt` dirty →
`LAND READY -> ARCHIVED` exit 0; target got `other.txt`, `app.txt` stayed
`before`. Partial land reported as success.

### H5. `sandbox apply` accepts the internal `controlPlane` escape hatch from the CLI
`.claude/harness/runtime/core/cli-router.mjs:210`

```js
else if (values[0] === "apply") {
  const { flags, rest } = parseFlags(values.slice(1));   // loose, not strict
  applySandbox(rest[0], flags);
}
```

The one `authority`-kind command routed through loose `parseFlags` — no key
normalization, no allowlist — so `--controlPlane` lands in `options.controlPlane`
verbatim and defeats the multi-repository guard at `apply-runtime.mjs:276`.
`commands.json:62` documents the usage as `sandbox apply <change>`, no flags.
Also exposes `--refresh`, which has no internal caller at all.

Consequence: the control-plane projection is written into the target before any
child repository has landed a commit, before CI, and before root submodule
pointers are staged. (`archive` still blocks later, so this is an out-of-order
working-tree mutation, not a full archive bypass.)

### H6. Service spawn failure crashes the harness and orphans already-started services
`.claude/harness/runtime/core/process-runtime.mjs:143-157`
(found independently by two agents)

`startServiceSession` registers `close`, `stdout`, `stderr` — but **no `error`
listener**. Node rethrows an unhandled `error` as an uncaught exception,
asynchronously, so the `try/catch` in `startRequiredServices`
(`adapter-runtime.mjs:49-58`) that exists precisely to stop already-started
sessions never runs. Service commands are never pre-checked: `commandExists` is
applied to *provider* commands only.

Trigger: an `execution.yaml` service whose `command[0]` doesn't resolve.
Verified on Node v26.3.0 that this terminates the process.

Consequence: raw `spawn … ENOENT` stack trace instead of the typed
`service '<name>' exited before readiness` failure; earlier services keep running
and hold their readiness ports, so the next proof run fails differently on port
conflict. `activeProofRun` is never cleared.

### H7. `install.sh` permanently deletes the user's `.claude/hooks/tests/` tree
`install.sh:242-244` (LEGACY entry at `install.sh:97`) — **reproduced**

`.claude/hooks/tests` is `rm -rf`'d unconditionally on every install, **after**
the MANAGED copy, and the backup taken at `install.sh:133-138` is discarded on
success. An entirely plausible path for a user's own hook tests.

Reproduced: created `.claude/hooks/tests/my-hook-test.sh`, ran
`install.sh <target> --yes`, file destroyed — no backup, no prompt. The
interactive path prints one line mislabeling the user's directory as Foundation
legacy; `--yes` skips even that.

**Scope note (a conflicting agent report was adjudicated here).** Removing the
*packaged* copy from the target is intentional —
`run-installer-tests.sh:153` asserts `assert_file_absent "obsolete packaged hook
tests removed"`. The bug is that the `rm -rf` is unconditional and cannot tell a
stale packaged copy from a user's own files at the same path.

Same root, second defect: `.claude/hooks/tests` **also exists in the shipping
source** — 5 files, nested under dot-directories
(`fixtures/{pass,fail}/.workflow/…`, which a shallow `find` misses) — so `cp -R`
at `:205` copies them in and `:243` deletes them moments later. The manifest is
written from the source tree before the deletion. Verified on a fresh install:
target has no `.claude/hooks/tests`, yet `install-manifest.txt` lists all 5 paths
as Foundation-owned.

### H8. Every hook command in `settings.json` is an unquoted path — all hooks break on a path with a space
`.claude/settings.json:9,21,31,43` — **reproduced**

All four `command` entries are bare `${CLAUDE_PROJECT_DIR}/.claude/hooks/...`.
`type: "command"` hooks are shell-executed, so a project at
`/Users/x/My Projects/foo` word-splits:

```
$ sh -c "${CLAUDE_PROJECT_DIR}/.claude/hooks/protect-secrets.sh"
sh: /Users/x/My: No such file or directory     rc=127
```

The two PreToolUse guards then **fail open silently**: `protect-secrets.sh` never
runs (secret reads proceed) and `phase-mutation-guard.mjs` never runs (phase
policy unenforced). `install.sh:264-277` propagates these exact strings into
every adopting repo.

### H9. JSON body `null` crashes the dashboard on `/api/heartbeat` and `/api/profile`
`dashboard/server.js:750`, `:1064` — **reproduced**

`JSON.parse('null')` is a *successful* parse yielding `null`; both handlers then
dereference `body.value.<field>`. The dispatcher discards the returned promise,
so it is an unhandled rejection → process death under Node's default.

Any holder of the shared key — every dev machine running `client.sh` — kills the
server with one request, or does it by accident. The caller sees curl `000`, so
it looks like a network fault.

`playwrightReportSummary` harvests every `annotations[].type === "claim"`

### M5. Review-history chain validation permanently blocks any change migrated at round ≥2
`.claude/harness/runtime/evidence/review-attempt-store.mjs:79` — **reproduced**

The walk-terminates-early fallback checks whether the *chain head* is migrated,
but migration puts the synthetic attempt at the chain *base*. Once a real attempt
is appended, the head is no longer `migrated`, so a sound chain is declared
corrupt:

```
chain valid after migration: true
reserved attempt: 3
chain valid after 1 real attempt: false   -> BLOCKED:review-history-corrupt
```

The offered remedy ("restore from backup") is unactionable — nothing is corrupt.
Only `abandon` unblocks the change.

### M6. Host-execution top-level `usage`/`cost` is silently dropped from telemetry and budget
`.claude/harness/runtime/observability/host-execution-contract.mjs:124-146` — **reproduced**

`normalizeHostExecution` persists a top-level `usage` block, but
`hostExecutionTelemetryRows` builds rows exclusively from `attempt.usage` — the
shape the schema declares as first-class never reaches `events.jsonl`.

With `usage:{inputTokens:120000, outputTokens:8000, cost:3.75}`:
`attempts: []` → 0 telemetry rows; one attempt without `usage` → a row with all
tokens and cost `null`. So `import` prints `imported 0`, `metrics` reports
`cost: null`, and budget gating never trips on host-side spend. The schema
requires `attempts` but sets no `minItems`.

### M7. A failed `proof collect` leaves `activeProofRun` set → next receipt binds a stale workspace hash
`.claude/harness/runtime/evidence/proof-execution-runtime.mjs:39,47,75-82`

`die()` calls `process.exit()`, which does not run pending `finally` blocks.
`proofCollect`'s cleanup lives only in `finally`, and its `catch` dies without
clearing first — unlike `proofExecute`, which clears before dying.

Consequence: `recordReceipt` prefers `state.activeProofRun?.workspaceHash` over
the live hash, so a subsequent human review receipt is stamped with the pre-fix
hash and lands in the dead `collect-…` directory. `receiptValidity` later returns
`stale` — the most expensive evidence in the system must be redone for no reason.

### M8. Declared provider readiness is enforced only for the Playwright adapter

Consequence: the suite runs against whatever occupies the port, exits 0, receipt
is `pass` while its own `observed` string says `readiness not-observed` — the

### M13. Read-only commands append to the operation log they report, including on archived changes
`.claude/harness/foundation.mjs:169`

### M16. `phase-mutation-guard.mjs`: `looksMutating` misses `git rm`, `cherry-pick`, `revert`, `stash`, `sed -i`

### M20. Archived-change lookup matches by id suffix
`.claude/harness/runtime/core/state-runtime.mjs:54`

`entry.name === id || entry.name.endsWith(`-${id}`)` is meant to strip OpenSpec's

surface for C3 and can write the wrong `state.archivedChangePath`.

## Test-suite health

`sh .claude/tests/run-all.sh` failed on the first run of this audit: 6 assertions
across two suites (harness contracts 4/316, installer smoke 2/135), all in
budget/telemetry migration. Both suites passed standalone, and two subsequent
full runs passed clean.

**Most likely cause: a concurrent working tree, not flaky tests.** A separate
feature workstream was editing the harness during this audit (see below), so the
first run executed against a partially-edited tree. A transient
`TypeError: openSpecCliStatus is not a function` during `install.sh`'s
post-install doctor — which rolled the install back — appeared in the same
window and then stopped reproducing, consistent with the same cause. Treat the
6 failures as an artifact unless they recur on a quiescent tree.

The underlying observation still stands: `run-all.sh` gives no signal that the
tree changed under it, so a mid-edit run reports confusing product failures
rather than "tree is dirty".

Not a bug: the legacy budget migration itself is correct in a properly installed
project (`runtime-upgrade`, lifetime `900000`, window `0`, state unchanged) — an
initial lead here was traced to an invalid hand-built fixture and dropped.

Coverage gaps worth noting: `runtime/reliability/bounded-retry.mjs` is correct as
written but is imported **only by its own test** — no runtime code calls it.
`run-harness-tests.sh:57` covers only `describe packet`, which happens to match
exactly, so the M1/M2 drift is untested.
