# v3.5.4 lifecycle safety remediation plan

**Date:** 2026-09-04  
**Target:** v3.5.4  
**Scope:** post-v3.5.3 review findings in Land authority, Build containment,
semantic amendments, and rich semantic references

The public lifecycle remains `/investigate`, `/change`, `/build`, `/prove`,
`/land`, and `/dev`. No command is removed and users do not gain a new manual
step. The compiled OpenSpec packet remains the agreement source of truth; this
report records the remediation and acceptance plan without copying the full
workflow contract from [WORKFLOW.md](../../WORKFLOW.md).

## Findings and decisions

| Finding | Failure mode | Remediation |
|---|---|---|
| Land inferred delivery authority | Active Land allowed commit/push variants without the runtime transaction marker | Require the marker for every mutating Land shell command; perform separately authorized delivery only after archive |
| Build shell checks covered too few path forms | Absolute operands, a later `cd`, and symlink traversal could leave isolation | Centralize canonical target inspection and apply it to filesystem operands, directory changes, redirections, hooks, and `exec` |
| `exec` did not own its Build cwd | A command could start in the caller's checkout or record a caller-supplied false phase | Derive phase from runtime state, reject mismatches, validate the workspace, and spawn from its canonical path |
| Semantic amendments accepted discarded fields | `updateTasks[].outcome` and `.verify` validated but did not update the ledger | Reject replacement explicitly and require a new task when outcome or verification semantics change |
| Rich references were lexical and permissive | Directories, escaping symlinks, non-HTTPS URLs, and floating version aliases could validate | Require contained regular local files and HTTPS remote sources with fixed versions |

## Implementation boundaries

- Runtime policy lives in
  `.claude/harness/runtime/core/shell-mutation-policy.mjs`; the hook exports the
  same policy instead of maintaining a second interpretation.
- Build `exec` containment belongs to the observability runtime because that
  adapter owns process invocation and timing.
- Semantic amendment validation and reference validation remain in their
  existing workflow modules. They do not create a parallel schema or ledger.
- Canonical behavior changes are recorded in `openspec/specs/change/spec.md`.
  README, commands, hook/harness guidance, and website pages summarize and link
  the same contract in English and Thai.
- Archived OpenSpec deltas and dated historical findings are not rewritten.

## Mutation acceptance

The new `SEM-LIFECYCLE-SAFETY` suite must baseline the relevant focused tests,
apply exactly one fault at a time in a disposable copy, compile it, require the
named regression to fail, and restore the source. A crash, timeout, unapplied
edit, or generic failure is not a kill.

| Mutant | Exact contract it challenges |
|---|---|
| `MUT-LAND-DELIVERY-AUTHORITY-INFERRED` | Active Land cannot infer commit/push authority |
| `MUT-BUILD-ABSOLUTE-OPERAND-ALLOWED` | Absolute filesystem operands cannot escape Build |
| `MUT-EXEC-WORKSPACE-CWD-REMOVED` | Build `exec` starts in the canonical workspace |
| `MUT-AMENDMENT-TASK-CONTRACT-REPLACED` | Existing task outcome/verification semantics stay immutable |
| `MUT-SEMANTIC-REFERENCE-REALPATH-DROPPED` | Local rich references use canonical containment |
| `MUT-SEMANTIC-REFERENCE-HTTPS-DROPPED` | Remote integration references require HTTPS |

## Release acceptance

Before release, all of the following must pass on the shipped source cohort:

1. focused hook, `exec`, semantic draft, and amendment regressions;
2. `SEM-LIFECYCLE-SAFETY` with all six mutants killed and the aggregate semantic
   mutation portfolio with no invalid suite;
3. affected and full deterministic harness suites;
4. English/Thai documentation consistency and the website documentation build;
5. upgrade matrix, release preflight, local rehearsal, and release workflow dry
   run;
6. real v3.5.4 workflow completion, published GitHub release, tag, bottle, and
   Homebrew formula commit.

Generated `.foundation` reports, fixture repositories, website build output,
caches, and the user's unrelated working-tree changes stay out of the release
commit.
