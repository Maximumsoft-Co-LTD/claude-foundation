# Initial performance evidence matrix

This matrix maps every numeric performance gate in `docs/roadmap.md` to the
exact local probe and promotion rule. A self-reported `passed`,
`coverageComplete`, or `releaseEligible` flag is never sufficient: the release
assessor recomputes samples and semantics and requires source-frozen external
soak records on a named reference-machine series.

| Roadmap gate | Probe and measurement semantics | Release threshold and required coverage | Schema, integrity, and promotion condition | Current status |
|---|---|---|---|---|
| CLI help/status startup | `scripts/performance/run.mjs`; process invocation through stdout flush and exit, separately for `cloop --help` and `cloop status` | Five warmups and at least 30 correct samples per command; recomputed p95 `<250 ms` | `run-record.schema.json`; exact observations must match duration samples; clean exit and oracle; source/Cargo.lock/executable identity unchanged; named reference machine | Implemented; release eligibility remains conditional on the complete record |
| TUI ready | `scripts/performance/tui_probe.py`; real PTY, complete ready frame, keyboard `/status` response, then clean `/quit` | Five warmups, at least 30 correct samples; recomputed p95 `<750 ms` | Run-record schema plus assessor verifies frame, keyboard response, clean exit, and no provider guidance | Implemented; release eligibility remains conditional on the complete record |
| Local event relay | `changeloop-performance-probes relay`; stdio, Unix socket, and HTTP+SSE with ordered receipt | For every transport: idle and four-concurrent-instance steady variants, 10,000 events, no drops, observed bounded queue depth, verified backpressure, recomputed p95 `<50 ms` | Run-record schema requires three transports/two variants in release records; assessor checks exact transport/variant names, counts, concurrency, order, queue depth/capacity, backpressure and raw samples | Smoke passed: idle/steady p95 was 2.77/3.74 ms stdio, 3.21/9.06 ms Unix, 3.30/10.02 ms HTTP+SSE; release sampling/source freeze still required |
| Graceful shutdown | `changeloop-performance-probes shutdown`; idle plus owned provider, child, PTY/job, LSP and backpressured-client resources; storage probe checks interrupted-operation recovery | Idle plus five active states, at least 20 samples/state, all terminal, zero forced cleanup; recomputed p95 `<2 s` | Run-record schema requires six states for release; assessor matches exact state set and terminal samples | Smoke passed all states, zero forced cleanup; slowest was LSP at 5.33 ms; release repetitions/source freeze still required |
| Eight-hour bounded growth | `reliability_probe soak` plus `mixed-soak-v2.mjs`; all 11 semantic workloads per cycle with process-tree RSS/FD/orphan and fixture-growth sampling | Two distinct uninterrupted records, each `>=28,800 s` and `>=100` successful cycles; zero workload failures/orphans/database growth; bounded RSS, FD, fixture growth and slopes | `storage-soak.schema.json` and `mixed-soak.schema.json`; atomic fsync+rename publication; start/end Git/source/lockfile/runner/probe/executable hashes must match | Diagnostic records completed but current assessor rejected both: storage 28,800.0004 s/31,730,226 exact cycles/0 database growth lacked current integrity schema; mixed 28,822.541 s/2,361 cycles had 59 failures and old five-workload/no-integrity shape. A new source-frozen qualification run is required |
| Provider router overhead | `changeloop-performance-probes router`; interleaved direct-versus-routed hermetic adapter fixtures | Exact 10-case OpenAI/Anthropic matrix (short, long, tool, large streaming and native non-streaming), 30 paired samples/case; identical events, one attempt, no retry backoff; recomputed aggregate and each case `<5%` | Run-record schema fixes matrix shape and fixture scope; assessor recomputes every ratio from raw nanoseconds and rejects duplicates/unsupported cases/upstream-performance claims | Diagnostic only: 8 streaming cases pass; both native non-streaming cases are unsupported |
| Reconnect/replay 10,000 events | `reliability_probe replay`; a fresh child process opens SQLite and performs cursor replay for every sample | Exact cold (`0` warmups) and warm (`5` warmups) variants, at least 20 samples each, exact count/order, zero duplicates, sampled RSS growth no greater than 64 MiB; recomputed p95 `<2 s` | Run-record schema requires two variants and raw latency/memory samples for release; assessor recomputes maximum RSS growth and matches exact variant names/counts | Smoke passed: cold 48.66 ms/5,984 KiB growth and warm 46.30 ms/5,616 KiB growth; full release sampling still requires 20 samples/variant and five warmups |

Release evidence additionally requires `--mode release --confirm-8h`,
`--reference-machine-id`, `--reference-series`, both external eight-hour records,
and unchanged identity throughout the run. The current implementation therefore
does not claim these initial gates—or GA as a whole—are complete.
