# Change: ทำให้เอกสาร Change มีรายละเอียดที่ใช้ตัดสินใจและลงมือทำได้ พร้อมเขียนเนื้อหาด้วยภาษาของผู้ใช้

## Why

ปัจจุบัน workflow เน้น draft ขนาดเล็กและกำหนดภาษาผู้ใช้เฉพาะคำตอบท้ายงาน จึงอาจได้เอกสารที่ผ่านโครงสร้างแต่ขาดบริบท ขอบเขต และเงื่อนไขตรวจรับ ผู้ใช้ต้องอ่านข้อตกลงได้โดยไม่ย้อนหาแชต

## What changes

- เพิ่มเกณฑ์รายละเอียดใน workflow ของ Change ครอบคลุมปัญหาปัจจุบัน ผลลัพธ์ที่ต้องการ ขอบเขต พฤติกรรมหลักและกรณีผิดพลาดที่เกี่ยวข้อง งานและวิธีตรวจรับ
- ให้เนื้อหาที่ agent เขียนใน packet ใช้ภาษาที่ผู้ใช้ระบุ หรือภาษาของคำขอปัจจุบัน โดยรักษาโครงสร้าง OpenSpec และตัวระบุเดิม
- ตรวจเนื้อหาใน packet ที่ compile แล้วก่อนส่งต่อ และอธิบายสัญญาเดียวกันใน README อังกฤษและไทย

## Impact

- **Impact:** low
- **Coupling:** isolated
- **Affected surfaces:** code
- **Security triggers:**

## Non-goals

- ไม่เพิ่มฟิลด์บังคับ เปลี่ยน protocol หรือแปลชื่อฟิลด์และเครื่องหมายที่ parser ใช้
- ไม่แปลย้อนหลังทั้ง repository หรือเพิ่ม artifact ที่ไม่มีเหตุผลด้านพฤติกรรม
