🧑‍🤝‍🧑 Team Mode — divide work by role v2.1

/dev runs the whole pipeline at once, but real teams split the work. v2 breaks it into 5 role-scoped commands that all write into the same run folder — they still compose into one resumable run via /dev --resume <id>.

CommandOwnerDoes
/specPMInterview + write spec.md
/dev-planTech LeadWrite the implementation plan.md
/test-planQADesign the test strategy before any code
/uxui-planDesignerDesign Scenes / wireframes / user flows
/implementEngineerGate → autonomous build through to ship

Later (v2.3 / v2.5.4), the Phase-1 slices (plan/test/uxui) became truly parallel — each writes its own state shard (no clobbering), and the gate folds them together.

✅ Test-first — know how it's proven before code v2.0–v2.2

  • test-plan.md (Phase-1 step 2½) — maps every acceptance criterion (happy path and its on error / at boundary clause) to the test level that owns it, written before a single line of code and signed off at the gate alongside the spec.
  • Coverage floors on the diff — unit ≥80% · integration ≥70% · e2e ≥50% of critical journeys (measured on changed code only; a ratchet, not a hard wall).
  • Visual verification — UI-touching changes get screenshotted and eyeballed, catching defects DOM assertions miss (e.g. a title breaking mid-word on a phone).
  • a11y + contract tests — axe-core in the same browser session + a contract test whenever an API/event contract is declared.

🎨 UX/UI as a first-class citizen v2.1–v2.5

  • uxui agent + uxui-plan.md — Scenes (including the empty/error states everyone forgets), Scenarios, UX direction, and an AC↔scene mapping that catches orphan scenes (scope creep) and unmapped ACs (design gaps).
  • ASCII wireframes are now a required part of every scene (v2.5.0) — see the layout before any code.
  • The engineer builds to the approved design (v2.5.4) instead of guessing the layout.
  • DESIGN.md — documents the UX/UI of an existing codebase via /init-project-docs.

⚡ Right-size to the work — and go faster v2.0.2–v2.5.0

  • Greenfield vs brownfield axis is first-class — work on existing code enforces the understand → lock → change discipline (a characterization baseline so the old behaviour can't silently break); new code skips it.
  • Patch lane — a tiny one-file change with no risky behaviour takes a shortcut instead of paying full process cost.
  • e2e + visual are opt-in (default off) — no more downloading Chromium every run; tests are noticeably faster, turn it on when you need it.
  • single-pass-first (v2.4) — fanout fires only when it clearly pays, not by default.
  • Size scorecard — helps decide XS/S/M/L for borderline work.

🔀 Parallelism done safely v2.0–v2.3

  • Fanout is planned, gated & recorded — a ## Fanout plan in plan.md, signed off at the gate, with every outcome logged to fanout_log for retro to review.
  • Surface (per-repo) fanout — a multi-repo control-plane run reviews/security/tests each repo in parallel, then merges the results.
  • State durability — fixes for state clobbering under concurrent runs/resume, and collision-proof follow-up IDs.

🧹 Leaner prompts, sharper interview v2.3.1–v2.5.7

  • 16 rule files → one router (fundamentals.md) — one file loaded per turn instead of sixteen; the full skill body still loads on demand.
  • Terse-output is now an always-on rule — concise, but never lossy.
  • grill-me interview (v2.5.7) — questions walk the design tree (resolve the decision others depend on first), every choice leads with a (Recommended) option to veto rather than author from scratch, and glossary + ADR are captured as you talk.
  • clarify-before-spawn — team slices ask the open questions in their own remit before starting.

📚 Onboard an existing codebase v2.2–v2.3.2

/init-project-docs reads the real code and generates an 8-doc suite — OVERVIEW · ARCHITECTURE · TECHSTACK · DATAMODEL · COREFEATURE · BUSINESSRULE · API · DESIGN — plus a self-contained document.html viewer.
