✅ Test-first — รู้ว่า พิสูจน์ยังไง ก่อนเขียนโค้ด v2.0–v2.2

  • test-plan.md (Phase-1 step 2½) — map ทุก acceptance criterion (ทั้ง happy path และ on error / at boundary) ไปยัง test level ที่รับผิดชอบ เขียน ก่อนมีโค้ดสักบรรทัด และ เซ็นอนุมัติที่ gate พร้อมกับ spec
  • Coverage floors บน diff — unit ≥80% · integration ≥70% · e2e ≥50% ของ critical journeys (วัดเฉพาะโค้ดที่เปลี่ยน เป็น ratchet ไม่ใช่กำแพงตายตัว)
  • Visual verification — งานที่แตะ UI จะ screenshot แล้ว "ดูด้วยตา" จับบั๊กที่ DOM assertion มองไม่เห็น (เช่น ข้อความตัดคำกลางคำบนมือถือ)
  • a11y + contract tests — axe-core ในเซสชันเบราว์เซอร์เดิม + contract test เมื่อมี API/event contract

🎨 UX/UI เป็นพลเมืองชั้นหนึ่ง v2.1–v2.5

  • agent uxui + uxui-plan.md — Scenes (รวม empty/error states ที่มักลืม), Scenarios, UX direction และ AC↔scene mapping จับ orphan scene (scope creep) และ AC ที่ไม่มีดีไซน์ (design gap)
  • ASCII wireframes กลายเป็นส่วนบังคับของทุก scene (v2.5.0) — เห็น layout ก่อนเขียนโค้ด
  • engineer สร้างตามดีไซน์ที่อนุมัติ (v2.5.4) ไม่ใช่เดา layout เอง
  • DESIGN.md — เอกสาร UX/UI ของ codebase ที่มีอยู่แล้ว ผ่าน /init-project-docs

⚡ ปรับขนาดให้พอดีงาน + เร็วขึ้น v2.0.2–v2.5.0

  • แกน greenfield vs brownfield เป็น first-class — งานบน codebase เดิมบังคับวินัย understand → lock → change (จับ baseline กันของเดิมพัง) ส่วนงานใหม่ข้ามได้
  • Patch lane — งานจิ๋วแบบไฟล์เดียวไม่มี behaviour เสี่ยง ใช้ทางลัด ไม่ต้องจ่ายค่ากระบวนการเต็ม
  • e2e + visual เป็น opt-in (default off) — เลิกโหลด Chromium ทุกครั้ง เทสต์เร็วขึ้นชัดเจน เปิดเมื่อต้องการ
  • single-pass-first (v2.4) — fanout ยิงเมื่อคุ้มจริงเท่านั้น ไม่ใช่ default
  • size scorecard — ช่วยตัดสิน XS/S/M/L งานก้ำกึ่ง

🔀 ทำงานขนานอย่างปลอดภัย v2.0–v2.3

  • Fanout วางแผน/อนุมัติ/บันทึกได้ — ## Fanout plan ใน plan.md, gate เซ็นอนุมัติ, fanout_log ให้ retro รีวิว

  • State durability — แก้ปัญหา state ชนกันตอนรันขนาน/resume และ follow-up ID กันชนกัน
