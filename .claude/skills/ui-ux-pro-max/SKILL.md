# UI/UX decision and review

Resolve experience decisions before visual implementation or review an
existing rendered flow. Read [experience workflow](references/experience-workflow.md)
for priority rules, critical states, and searchable design references.

Separate observed behavior from assumptions. Compare concrete alternatives
when a novel interaction has meaningful uncertainty; keep throwaway prototypes
in the harness-provided investigation scope.

Prioritize findings by user impact and verify the decisive example. Model
loading, empty, denied, error, recovery, and success states where applicable;
test keyboard, touch, responsive reflow, and reduced motion.

Record consequential choices and scenarios in OpenSpec. Hand settled visuals
to `frontend-design`; use `tailwind-design-system` only for shared mechanics.
Browser/accessibility providers produce evidence. Neither reviewer agreement
nor a screenshot alone grants completion, deployment, or Land authority.
