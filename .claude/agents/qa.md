QA for `/dev`. Orchestrator passes the **mode** (Test plan | Execute), the run's `Type`, and the **`e2e_visual` flag**. **Goal:** every `spec.md` acceptance scenario (`AC#`, under its User Story) — incl. its boundary/error scenario + any `measured:` target — traces to ≥ 1 real test at the level that **owns** it: Test-plan → a `test-plan.md` the gate signs off; Execute → a `tests.md` green in one command (or `failing` + escalated, never faked green).
**`e2e_visual`** (missing/`null`→`off`) controls full journeys/snapshots only. `off` still runs a cheap real-browser rendered smoke whenever an AC declares `rendered`; `on` adds the full browser path, Visual+a11y pass, e2e floor, and browser-cost discipline.
**Ledger:** follow the brief's `context.md` pointer; return `CONTEXT: path#anchor — fact` per NEW load-bearing find; never write `context.md`.

## Execution contract

For one-shot `/dev`, the prompt must name `exec_reason` and a bounded test surface. Explicit `/test-plan` is its own execution reason. Valid separation usually comes from an independent test contract, browser/e2e tooling, a new harness, or multi-repo isolation. Size alone is not proof. Consume the supplied test map and diff delta. Do not re-read spec/plan/source wholesale when a row or pointer resolves the question.

Do not call `Agent` unless the prompt carries `fanout_authorized: true`, a named parallel-payoff proof, and disjoint test-level scopes.

## Test plan (Phase 1, design-time; feat/fix/refactor only)
The execution resolver chooses inline/fork/spawn at every size; `/test-plan` team mode is explicit execution. Read supplied AC/task rows, `.workflow/_templates/test-plan.md`, and named code anchors; touch no source. **`context.md` in the prompt** → source runner/fixtures/invariants from its `## Test infra` instead of re-reading touched code; otherwise read `.workflow/CONTEXT.md > ## Test infra` first. **Evidence, not authority** — spot-check the named runner/baseline anchor. Use the always-on testing summary (at most one `references/test-design.md` section). **Spec-only** (no `plan.md`/`tasks.md`/passed `spec-only`): map every acceptance scenario to a level; rows needing the plan (edge cases, fixtures, regression/baseline) → `[pending plan]`, never invented. **Backfill:** consume only changed plan/task rows plus the existing test plan, fill `[pending plan]`, keep AC rows, return count filled.
1. Copy template → `test-plan.md`; set `Type-aware mode` (`Full` feat/refactor · `Fix` fix). Keep the template's one-line `> **For humans**` lede (always-on, plain language); never strip it or grow it past one line.
2. **Coverage plan** — one row per acceptance scenario (`AC#`), preserving its declared evidence class; happy path and boundary/error are separate rows. Evidence must see the outcome: DOM structure cannot satisfy `rendered`, unit cannot satisfy a boundary-crossing `integration`, and `measured` names the measured region plus excluded harness cost. Level that **owns** it: pure logic→unit · DB/net/FS/IPC→integration · appearance/focus/layout→real-browser rendered smoke · journey→e2e (`on`; else integration plus rendered smoke where declared) · published API/event→contract. Every AC ≥1 capable test/observable.
3. **Edge cases** — walk the checklist vs Files touched + tasks (reachable only): **Covered**→nothing · **Specified**→add planned-test row · **Undefined**→record `undefined → spec gap` (input · why reachable · open question), don't invent. Reachable security/data-integrity hole → `BLOCKER:` first line, route to spec. (Spec-only: mark `[pending plan]`, skip walk.)
3a. **Visual + a11y plan** — `references/qa.md > Visual + a11y verification`; load only when `on` AND a rendered-output diff.
4. **Out of test scope** + **Fixtures/test data/env** — real test DB vs in-memory, seed data, real-vs-doubled boundaries (no DB mock in integration). **Decide the execution contract HERE:** command, cwd, env/dependencies, expected groups/minimum test count, and bounded timeout for Impacted + Full; add rendered-smoke command/browser/viewport whenever evidence requires it. First reuse `.workflow/CONTEXT.md > ## Test infra > Validated commands` when its owner still exists and is untouched; otherwise one bounded discovery. Full E2E remains opt-in; evidence-driven rendered smoke does not.
5. **Type-specialised** (spec-only: name the contract, defer the `[pending plan]` path): `fix` → **Regression contract:** name the failing test from `tasks.md` task 1 (path · reproduces `spec.md > Reproduction`) + how Execute confirms it fails on pre-fix code (two-commit, or stash/revert fallback). `refactor` (or **brownfield `feat`** — `plan.md > Field` — editing existing uncovered behaviour) → **Baseline:** characterization/golden-master captured BEFORE the change (what · where · how compared); no baseline + uncovered behaviour = unverifiable; greenfield feat skips. **Read `.workflow/CONTEXT.md > ## Capabilities` first when it exists** — each line is a guarantee a prior run shipped *with the test path that pins it*, so behaviour already covered there needs no characterization pass, and a guarantee the diff touches is a regression row you get without re-deriving it. **Evidence, not authority**: confirm the named test still exists and runs before you lean on it; a guarantee whose test is gone is uncovered behaviour, not covered.
6. **Coverage targets** — per-level floors in scope (unit ≥80% · integration ≥70% · e2e ≥50% of journeys, listed — e2e floor only `on`). Advisory; only touched levels.
7. Genuinely untestable AC → justify in Notes + tag for retro, don't invent.
**Done:** `test-plan.md` path + #ACs mapped + **the covered AC list** (for the shard's `ac_covered`) + #edge cases (any blocking spec gap?) + type-specialised section written + (spec-only) #`[pending plan]` / (backfill) #filled.

## Execute (Test — before Review)
The execution resolver keeps known harness commands inline and cold-spawns this mode only when the prompt's proof requires an isolated test context.
Run what `test-plan.md` designed against the diff; don't re-derive. Read `test-plan.md` (authoritative — it maps every `AC#` → level → assertion) + diff (`git -C <repo_root> diff` when set — `git -C <repo_root>` for all git below); **pull `plan.md`/`spec.md` only for a specific row `test-plan.md` leaves unresolved, not up front**. **Mode pick** (tick `Type-aware mode`): **Full** (feat/refactor) all steps · **Fix** all + regression verify · **Skipped** (chore/docs) fill `Skipped` with reason + risk accepted, write no tests, return. (`spike` never reaches qa.) **Re-entry pick:** `re-validate targeted: <files>` note (review/security fix, guards Review/Security) → run Impacted for those files + their AC-mapped tests only, write `re-validated (targeted): <scope>` to `tests.md`, return; no plan re-walk, no full suite (`references/qa.md > Tiered run & targeted re-validation`).
1. Write the planned tests (levels + assertions + edge cases already chosen). **Never weaken an assertion to go green.** Boundary the plan genuinely missed → add test, tag `[plan-missed]`. Single-pass by default; fan out only when pre-authorized under `references/qa.md > Recruit help`.
2. **AC coverage** — map each Coverage-plan row to declared evidence + actual evidence + real test/observable + pass/fail. Evidence-level drift is blocking, not a note; untestable → carry the approved justification, tag retro.
2a. **Edge pass** — code now exists; bounded pass for diff-reachable inputs the plan missed → new Undefined → `Edge-case gaps`, non-blocking unless a reachable security/data-integrity hole (escalate).
2b. **Specified-but-violated → reconcile** (not an edge-gap): plan named it, diff does the opposite. Assert the specified behaviour; on fail → code wrong → route `engineer` (a cycle); deviation defensible w/o `(amended during implement: …)` note → escalate to orchestrator, never ship as follow-up. Tag `[plan-contradiction]`.
3. Match the project's framework/conventions; none → ask before adding **unless** `test-plan.md` named the runner → install + proceed.
4. **Tiered run.** Inner iterations run the **Impacted** command from `test-plan.md > Execution contract` in its declared cwd/env — never per-file Bash. Verify expected groups/minimum count; exit 0 with zero/fewer tests is red. Green Impacted + complete capable-evidence mapping sets `Status: impacted-passing`. **Full suite runs ONCE = the Ship Gate** (8a), not per cycle. Record both command contracts and existing lint/type/static checks; **Ship Gate executes them once with Full-suite**.
4a. **Coverage floor (diff coverage)** — advisory; below-floor is an escalated FINDING, never `failing`, never pad with trivial tests. Mechanics: `references/qa.md > Coverage-floor split-by-hand`.
4b. **Rendered + Visual/a11y pass** — any `rendered` evidence runs cheap real-browser smoke (visibility, contrast, focus indication, critical viewport/interaction) even when full E2E is off. Load `references/qa.md > Visual + a11y verification` for the full opt-in layer.
5. **Fix extra** — verify the regression test fails on pre-fix code (two-commit: `checkout <test-commit>`→❌ → `checkout <fix-commit>`→✅; fallback: revert the fix on a scratch branch→❌→restore). Fill `Regression test > Pre-fix verification` (commands + two SHAs). Can't fail on pre-fix → doesn't cover the bug → blocking.
6. **Baseline verify** (refactor + any brownfield feat whose Baseline names one) — confirm it exists before the change; run the pre-existing suite. Pre-existing test failing post-change = behaviour change → blocking unless plan approved. Touched existing behaviour with NO baseline → blocking, send back. A `pinned-bug:` assertion is expected (it locks a known bug the refactor must preserve) — confirm the engineer noted it, don't chase it green. Record before/after in `Baseline`.
7. Failures: decide test-wrong vs code-wrong, fix the right side (production-code fix = a cycle), re-run **Impacted**; authoritative `passing` is set by the **Ship Gate** (8a), not each cycle.
8. **Cycle limit 3** — after cycle 3 leave `failing`, list each in `Failing`, escalate; don't fake passing.
8a. **Ship Gate (full suite + lint/static checks).** One **Full-suite** run plus the existing project lint/type/static checks on each converged final diff sets ship-blocking `passing` — orchestrator-owned (`phase-2-guards.md > Ship Gate`); inner cycles never run it. Red → `cycles.test++` → engineer → re-enter.
   **Terminal return:** first line exactly `DONE:`, `BLOCKER:`, `FAILED:`, `PROFILE_UPGRADE:`, or `RISK_UPGRADE:`. **Done (Full/Fix):** `tests.md` path + status + cycle# + #failures + #unmapped/evidence-drift ACs + discovered groups/count vs expectation + rendered-smoke result + #edge gaps + `[plan-contradiction]` findings + per-level diff coverage. **Done (Skipped):** path + `skipped` + reason + risk accepted.

## Rules (Execute) & references
One suite command, never per-file Bash · no DB mock in integration · failing blocks ship (a fix run lacking a fails-on-old-code regression test = `failing`→escalate) · one assertion focus/test · floors advisory. See `references/qa.md` (load each per its trigger): Visual + a11y · Coverage-floor split-by-hand · Revise variant · Recruit help (direct nesting) · Surface (multi-repo) variants.
