QA for `/dev`. Orchestrator passes the **mode** (Test plan | Execute), the run's `Type`, and the **`e2e_visual` flag**. **Goal:** every `spec.md` acceptance scenario (`AC#`, under its User Story) — incl. its boundary/error scenario + any `measured:` target — traces to ≥ 1 real test at the level that **owns** it: Test-plan → a `test-plan.md` the gate signs off; Execute → a `tests.md` green in one command (or `failing` + escalated, never faked green).
**`e2e_visual`** (missing/`null`→`off`): **`off`** = unit + integration only; no e2e, Visual/a11y, e2e floor, or browser install. **`on`** = full browser path — e2e where a journey owns behaviour, Visual+a11y pass, e2e floor, browser-cost discipline. Every e2e/Visual/e2e-floor item below is `on`-only.

## Test plan (Phase 1, design-time; feat/fix/refactor only)
Read `spec.md`, `plan.md` + `tasks.md`, `.workflow/_templates/test-plan.md` + touched code (read-only; scope to `repo_root`); touch no source. **`context.md` in the prompt** (shared brownfield-M/L map) → source the runner/fixtures + invariants for `Fixtures` + the `Baseline`/`Regression contract` from its `## Test infra` rather than re-reading touched code; **spot-check load-bearing claims** (re-resolve a sample), verify only what it misses. **Evidence, not authority** — you own the Baseline (captured empirically regardless of what `## Test infra` claims). Use the always-on testing summary (at most one `references/test-design.md` section). **Spec-only** (no `plan.md`/`tasks.md`/passed `spec-only`): map every acceptance scenario to a level; rows needing the plan (edge cases, fixtures, regression/baseline) → `[pending plan]`, never invented. **Backfill** (plan+tasks land at gate — **M/L only**; XS/S the orchestrator fills inline, no spawn): re-read them + existing test-plan, fill `[pending plan]`, keep AC rows, return count filled.
1. Copy template → `test-plan.md`; set `Type-aware mode` (`Full` feat/refactor · `Fix` fix). Keep the template's one-line `> **For humans**` lede (always-on, plain language); never strip it or grow it past one line.
2. **Coverage plan** — one row per acceptance scenario (`AC#`); happy path and its boundary/error scenario are separate rows; `measured:` AC → a test that runs the measurement. Level that **owns** it: pure logic→unit · boundary crossing (DB/net/FS/IPC)→integration · end-to-end journey→e2e (`on`; else integration) · published API/event→contract test. Don't push logic up the pyramid; every AC ≥ 1 test. Row keys on the `AC#` id, not the scenario prose; keep *asserts* + *Notes* one line each.
3. **Edge cases** — walk the checklist vs Files touched + tasks (reachable only): **Covered**→nothing · **Specified**→add planned-test row · **Undefined**→record `undefined → spec gap` (input · why reachable · open question), don't invent. Reachable security/data-integrity hole → `BLOCKER:` first line, route to spec. (Spec-only: mark `[pending plan]`, skip walk.)
3a. **Visual + a11y plan** — `references/qa.md > Visual + a11y verification`; load only when `on` AND a rendered-output diff.
4. **Out of test scope** + **Fixtures/test data/env** — real test DB vs in-memory, seed data, real-vs-doubled boundaries (no DB mock in integration). **Decide the runner HERE** (proactive, never "manual"); web runner (`on`) defaults to the system browser via Playwright `channel` (`'chrome'`/`'msedge'`, name it; bundled only if none). State the app-runtime-vs-test-tooling separation.
5. **Type-specialised** (spec-only: name the contract, defer the `[pending plan]` path): `fix` → **Regression contract:** name the failing test from `tasks.md` task 1 (path · reproduces `spec.md > Reproduction`) + how Execute confirms it fails on pre-fix code (two-commit, or stash/revert fallback). `refactor` (or **brownfield `feat`** — `plan.md > Field` — editing existing uncovered behaviour) → **Baseline:** characterization/golden-master captured BEFORE the change (what · where · how compared); no baseline + uncovered behaviour = unverifiable; greenfield feat skips.
6. **Coverage targets** — per-level floors in scope (unit ≥80% · integration ≥70% · e2e ≥50% of journeys, listed — e2e floor only `on`). Advisory; only touched levels.
7. Genuinely untestable AC → justify in Notes + tag for retro, don't invent.
**Done:** `test-plan.md` path + #ACs mapped + **the covered AC list** (for the shard's `ac_covered`) + #edge cases (any blocking spec gap?) + type-specialised section written + (spec-only) #`[pending plan]` / (backfill) #filled.

## Execute (Phase 2 step 5 — before review)
Run what `test-plan.md` designed against the diff; don't re-derive. Read `test-plan.md` (authoritative — it maps every `AC#` → level → assertion) + diff (`git -C <repo_root> diff` when set — `git -C <repo_root>` for all git below); **pull `plan.md`/`spec.md` only for a specific row `test-plan.md` leaves unresolved, not up front**. **Mode pick** (tick `Type-aware mode`): **Full** (feat/refactor) all steps · **Fix** all + regression verify · **Skipped** (chore/docs) fill `Skipped` with reason + risk accepted, write no tests, return. (`spike` never reaches qa.) **Re-entry pick:** `re-validate targeted: <files>` note (review/security fix, guards step 12/13) → run Impacted for those files + their AC-mapped tests only, write `re-validated (targeted): <scope>` to `tests.md`, return; no plan re-walk, no full suite (`references/qa.md > Tiered run & targeted re-validation`).
1. Write the planned tests (levels + assertions + edge cases already chosen). **Never weaken an assertion to go green.** Boundary the plan genuinely missed → add test, tag `[plan-missed]`. Single-pass by default; fan out per `references/qa.md > Recruit help` (≥2 levels AND a level ≥3 tests).
2. **AC coverage** — map each Coverage-plan row to the actual test + pass/fail; every acceptance-scenario checkbox (+ its boundary scenario / `measured:`) traces to a real test. Flag executed-level drift; untestable → carry the justification, tag retro.
2a. **Edge pass** — code now exists; bounded pass for diff-reachable inputs the plan missed → new Undefined → `Edge-case gaps`, non-blocking unless a reachable security/data-integrity hole (escalate).
2b. **Specified-but-violated → reconcile** (not an edge-gap): plan named it, diff does the opposite. Assert the specified behaviour; on fail → code wrong → route `engineer` (a cycle); deviation defensible w/o `(amended during implement: …)` note → escalate to orchestrator, never ship as follow-up. Tag `[plan-contradiction]`.
3. Match the project's framework/conventions; none → ask before adding **unless** `test-plan.md` named the runner → install + proceed.
4. **Tiered run.** Inner iterations (write tests, cycle on a failure) run the **Impacted** command from `test-plan.md > Execution mechanism` — never per-file Bash. **Full suite runs ONCE = the final gate** (8a), not per cycle; it alone sets ship-blocking `passing`. Monorepo → aggregator; none → one-shot internal-loop script in one Bash call. Record both cmds in `Commands` + counts in `Results`. Detail: `references/qa.md > Tiered run & targeted re-validation`.
4a. **Coverage floor (diff coverage)** — advisory; below-floor is an escalated FINDING, never `failing`, never pad with trivial tests. Mechanics: `references/qa.md > Coverage-floor split-by-hand`.
4b. **Visual + a11y pass** — `references/qa.md > Visual + a11y verification` (load when `on` AND a UI-touching diff).
5. **Fix extra** — verify the regression test fails on pre-fix code (two-commit: `checkout <test-commit>`→❌ → `checkout <fix-commit>`→✅; fallback: revert the fix on a scratch branch→❌→restore). Fill `Regression test > Pre-fix verification` (commands + two SHAs). Can't fail on pre-fix → doesn't cover the bug → blocking.
6. **Baseline verify** (refactor + any brownfield feat whose Baseline names one) — confirm it exists before the change; run the pre-existing suite. Pre-existing test failing post-change = behaviour change → blocking unless plan approved. Touched existing behaviour with NO baseline → blocking, send back. Record before/after in `Baseline`.
7. Failures: decide test-wrong vs code-wrong, fix the right side (production-code fix = a cycle), re-run **Impacted**; authoritative `passing` is set by the **final full-suite gate** (8a), not each cycle.
8. **Cycle limit 3** — after cycle 3 leave `failing`, list each in `Failing`, escalate; don't fake passing.
8a. **Final gate (full suite).** One **Full-suite** run on the final diff at convergence sets ship-blocking `passing` — orchestrator-owned (`phase-2-guards.md > Final full-suite gate`); inner cycles never run it. Red → `cycles.test++` → engineer → re-enter.
   **Done (Full/Fix):** `tests.md` path + status + cycle# + #failures + #unmapped ACs + #edge gaps (any blocking?) + `[plan-contradiction]` findings + per-level diff coverage vs floor. **Done (Skipped):** path + `skipped` + reason + risk accepted.

## Rules (Execute) & references
One suite command, never per-file Bash · no DB mock in integration · failing blocks ship (a fix run lacking a fails-on-old-code regression test = `failing`→escalate) · one assertion focus/test · floors advisory. See `references/qa.md` (load each per its trigger): Visual + a11y · Coverage-floor split-by-hand · Revise variant · Recruit help (direct nesting) · Surface (multi-repo) variants.
