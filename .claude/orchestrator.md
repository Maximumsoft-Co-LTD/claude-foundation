# Orchestrator (main-agent role)

**Not a sub-agent** — sub-agents can't `AskUserQuestion`, so orchestration runs in the **main agent**; the `/dev` command reads this file. You drive the flow; sub-agents do the file work; you own **every `Agent` spawn, every `AskUserQuestion`, and the single-writer `state.json`**. Workers: `pm` `lead` `engineer` `qa` `retro`; fanout = `team-*`. **Never** `Agent(subagent_type="orchestrator")` (no such agent) and never fall back to `general-purpose`. Flow is **type-aware** (`WORKFLOW.md > Type-aware phase matrix`): interview → spec → plan → gate → autonomous Phase 2 → ship → retro. Think before coding, simplify first (single-pass default, size-aware machinery), keep diffs surgical, the acceptance criteria are the contract. **Step numbers:** this file uses ops **0–18**, `WORKFLOW.md`/agents use matrix **1–10** — cross-ref by **name**: Setup 0–5 = pre-phase · Interview/Spec 6/7 = 1 · Plan/Test-plan/Gate 8/8a/9 = 2/2½/3 · Implement/Test/Review 10/11/12 = 4/5/6 · Security 13 = 7 · Docs/Ship/Retro 14/15/16 = 8/9/10 · Skill-handoff/Done 17/18 fold into 10/terminator.

## Single-pass-first
Default to **one sequential spawn per phase**; fan out only when **all three** hold: (a) work decomposes into independent sub-investigations (no finding changes another), (b) helpers write **disjoint** files/symbols, (c) coordination + N× cold-start < wall-clock saved — else single-pass. Governs both push fanouts and `FANOUT_REQUESTED:` signals (a request to *evaluate*, not an order — honour when (a)–(c) hold, else refuse with a one-line reason). **Type forbids implement fanout** for `fix`/`refactor`/`spike`. **Never changes:** single-writer state, the synthesis pass when fanout fires (fanout output is evidence, never the artifact), pre-implement disjointness re-verification, and the gate.

## On invocation — Fresh run
0. **Not-actually-fresh guard.** Scan `.workflow/*/state.json` for non-`done` runs still in Phase 1; if the message reads as feedback on the latest such spec/plan, resume it into its gate `revise` path (step 9) — never spin a fresh Phase 1. Ambiguous → ask once; >1 in-flight → offer to close older (`INDEX.md` status `abandoned`).
1. Read `.workflow/INDEX.md` + `.workflow/FOLLOWUPS.md`; consult `WORKFLOW.md` only for the section needed.
2. **Repo detection.** `find . -maxdepth 2 -name .git \( -type d -o -type f \)` (match `.git` dir OR file — submodules). `./.git` only → single-repo `repo_root=$(pwd)`; any subdir `.git` → control-plane, ask once which repo is primary, record `state.repos`; no `.git` → no-git, `repo_root=null`, skip every VCS gate thereafter (append `ship:no-vcs` to `skipped_steps` at ship).
3. Pick run ID `NNNN-<type>-<kebab-slug>` (`feat|fix|refactor|chore|docs|spike`). Estimate size first (step 6 sub-step 0). XS/S → fold setup (type, branch) into the merged interview batch; M/L → ask ≤2 (type if unclear, branch). As soon as the branch returns: warn + offer default if not on main, then `git -C <repo_root> checkout -b <branch>` (exists → `checkout` + note `branch_existed=true`), confirm before proceeding. Skip only when `repo_root` null.
4. Create `.workflow/<id>/`.
5. Copy `_templates/state.json` → `.workflow/<id>/state.json`; fill `id type size field repo_root repos branch phase=phase-1-requirements step=interview` + timestamps (`created_at`=`last_updated`=`$(date -u +%Y-%m-%dT%H:%M:%SZ)` — **run the command; you have no clock, never type a timestamp from memory**), `done_at=null`.
6. Append `INDEX.md` row, status `spec`.

**Resume (`/dev --resume <id>`)** — mechanics (branch re-checkout, hard-stop on git failure, shard reconciliation, mid-fanout `step=implement` guard, legacy missing-`size`/`field`) → **`references/resume.md`** (read only when resuming).

## State discipline
At **every worker return, phase boundary, and fanout point** — the points `--resume` keys off and the guard enforces; orchestrator-only micro-steps that spawn nothing (gate option loop, INDEX touch) fold into the next such write — update `state.json`: for a routine per-step bump `Edit` the hot scalars in place (`step`/`next_step`/`last_updated`/`last_agent`/`cycles.*`); `Write` the COMPLETE object on any structural change (append to `fanout_log`/`skipped_steps`, `phase_plan`, shard fold). Every write MUST leave valid JSON with no duplicated key — an `Edit` **replaces** an existing key's value, never inserts a second copy (the two-`notes`-keys corruption that broke `--resume`); `dev-state-validate.sh` blocks the write and makes you fix it otherwise. Set `phase`/`step` = just-completed; `next_step` = next per matrix (skipped as `"skipped:<reason>"`); `cycles.review`/`cycles.test` bump only on real increments; **every timestamp = `$(date -u +%Y-%m-%dT%H:%M:%SZ)` output — run it, never guess (you have no clock; a hand-typed ISO is hallucinated)**: `last_updated` each write, `created_at` once at step 5, `done_at` once at step 16; `last_agent` = who just returned (`main` if you); `notes` = terse breadcrumb tags **not prose** (append a short clause per noteworthy event — `patch-lane`, `ci: unchecked`, `branch_existed=true`, `fanout refused — <reason>` — never restate artifact content, prune stale, keep cheap). At each fanout point (spec-prep 6, plan 8, implement 10, test 11, review 12, security 13) re-read `fanout_log` and **append** `{phase, eligible, fired, path, n, reason}`.
Hook-enforced: `dev-state-mark.sh` marks worker returns, `dev-state-validate.sh` rejects a write that leaves `state.json` malformed or with a duplicate key, `dev-agent-guard.sh` blocks the next spawn until `state.json` mtime is newer (**M/L only** — XS/S keep the write instruction but skip the hard block: few spawns, cheap to re-run) — on `BLOCKED by /dev guard`, write `state.json` then retry. Edge cases (background-spawn exemption, worktree `CLAUDE_DEV_RUN_ID`) → `references/state-edge-cases.md`; **Team-mode Phase-1 sharding** (`state.<slice>.json` written by team-mode commands, folded at gate) → `references/team-mode-sharding.md` (read each only when relevant). **Efficiency:** `state.json` + the returning summary are your working set — don't re-read artifacts; keep turns short (~5-min cache TTL): decide, write, spawn; fanout goes out in **one message**; pass `repo_root` + `branch` to every sub-agent; spawn prompts carry **pointers + the delta** (name the authoritative artifact, e.g. `read spec.md first — it is the contract`), not a paraphrase.

## Size-aware execution
Size *definitions* → `references/size-execution.md`; the *picker* + greenfield/brownfield *def* → `plan-writing > references/size-tiering.md`. The type matrix decides *which* phases run; **size decides how much machinery each gets** — estimate at step 6 sub-step 0. **XS** = one file / config value / one-liner, no new behaviour, no integration risk; **S** = ≤~3 files, one understood integration point (a self-contained greenfield module stays S even with multi-feature CRUD; a wide-but-shallow parallel sweep is sized by its deepest single surface); else **M/L**. Any persisted-data / schema / API-contract change is **never XS** (a greenfield app's own first-party storage is exempt). Torn → pick larger; `state.json > size` ratchets **up** only (larger plan `Size` = `SIZE_UPGRADE`; smaller never shrinks machinery). **Never shrinks at any size:** merged interview, gate per-line AC confirm, state writes, security-trigger check, type matrix. **Patch lane (XS):** one file/surface, no runtime behaviour/persisted-data/API/schema/dep/security path, no executable test surface, no cross-repo coupling → record `size=XS` + `patch-lane`, review/test/docs default cheapest matrix-safe; any discovered behaviour/contract/multi-file/cross-repo → `SIZE_UPGRADE: S`. **XS/S fast path** (deltas) → `references/xs-s-fast-path.md` (read when `size` ∈ XS/S). **`SIZE_UPGRADE: <S|M|L> — <reason>`** (worker first line) → raise `size`, run remaining at new tier, written artifacts stand, never moves down.
**Field (greenfield|brownfield, orthogonal, one-way).** Classify at digest, record `field`. **Default brownfield** unless genuinely new isolated code (every fix/refactor, every M/L, every mixed run is brownfield). Brownfield turns on **understand** (current-state map) + **lock** (characterization baseline). `FIELD_UPGRADE: brownfield — <reason>` → set `field=brownfield`, run remaining brownfield, **backfill** understand/lock: re-spawn `lead` plan-revise for `plan.md > Current state`; for `test-plan.md > Baseline` — M/L the `qa` spawn writes it, XS/S you add the row inline. Only ratchets greenfield → brownfield.

## Phase 1 — Requirements
6. **Interview (you run it** — sub-agents can't `AskUserQuestion`). Ingest prior conversation into a **requirements digest**, estimate `size` + classify `field`, fetch reference URLs, run spec-prep fanout (opt-in), pick the UNSPECIFIED slots **ordered by the design tree** (load-bearing first, defer dependents to a later batch), run the three detections (NFR / e2e-visual opt-in / error-boundary), `AskUserQuestion` **one batch of 3–4 — each choice leads with a `(Recommended)` option** — + a free-text catch-all, save the bundle for `pm`. Procedure → `references/interview.md`.
7. **Spec.** Spawn `pm` with run id, type, intent, digest+catch-all, full Q&A, references (URLs inlined), in-scope FOLLOWUPS IDs, spec-prep findings + `Dispatched-as:` map; it returns path + 3-bullet summary. `FANOUT_REQUESTED: research:` → dispatch then re-spawn. INDEX → `planned`; state `step=spec, next_step=plan`. **Spec check** (`spec.md`): `Type` set; User Stories (priority-ordered) + acceptance scenarios (`AC#`) + FR-### + SC-### present; each fired section's trigger holds; `fix` has concrete Reproduction; `spike` has hard Timebox; unresolved slots marked. Re-spawn only if a real answer was dropped.
8. **Plan.** **Plan-prep fanout first** — `repo_root` set AND `spec.md` names ≥2 integration points in **disjoint surfaces** → one `team-codebase-explorer` per point in one message (entry→flow→callers/blast-radius→invariants, each `path#anchor`); skip XS/S/pure-greenfield/single point. Then spawn `lead` plan mode (+ explorer findings + `Dispatched-as:` map) to write `plan.md` **+ `tasks.md`** (or `epic.md`), pass `Type`. **Model `sonnet` by default; keep opus** for L-tier (cross-subsystem, schema migration, public API/contract/breaking). `FANOUT_REQUESTED: plan:` → dispatch residual, re-spawn. INDEX → `planned`; state `step=plan`, `next_step=test-plan` (feat/fix/refactor) else `gate`. **Plan check** (`plan.md` + `tasks.md`): `tasks.md` has ≥ 1 `T###` task with an `[AC#]` tag + `verify:`; `plan.md` has a `## Phases for this task` block; no `[NEEDS CLARIFICATION]`. Fail → re-spawn once, then escalate.
8a. **Test plan** (feat/fix/refactor only; else append `test-plan` to `skipped_steps` → gate). XS/S already folded into the combined `lead` spawn (just run the check). M/L → spawn `qa` test-plan mode (pass `e2e_visual`; off → map journeys to integration, omit visual/e2e), writes `test-plan.md` (design only). **Check:** missing first line when type should produce one → re-spawn once; `BLOCKER:` → `AskUserQuestion`, route to pm/lead. State `step=test-plan, next_step=gate`.
9. **Gate.** **Fold Phase-1 shards first** (read each `state.*.json`, fold into `state.json`, re-emit once). **Test-plan backfill:** `pending_plan_backfill` (or `[pending plan]` remain) AND `plan.md` now exists → fill **once** first — **XS/S inline** (read `plan.md`/`tasks.md`, write the rows; no spawn), **M/L** re-spawn `qa` `backfill`. **Pre-gate consistency scan — set-compare first:** spec AC set vs each shard's `ac_covered` (plan=`tasks.md` tags · test=Coverage rows · uxui=Scenes) → **match → pass, no re-read.** Mismatch (or no `ac_covered`) → re-read that artifact + full check: every AC has delivering+verifying task(s) tagged in `tasks.md`, no dangling `T###` / phase ref, zero `[NEEDS CLARIFICATION]`, (feat/fix/refactor) every AC has a Coverage-plan row and no `[pending plan]` rows. Fail → one corrective re-spawn of the owner. Build the type-aware run plan from the matrix; **resolve ship disposition** — `commit_on_ship` **asked every run (default `no`)**, then `open_pr_on_ship` only if commit=yes (blank → ask once; commit=no forces it `no`); then **present the contract and run the option loop** → `references/gate.md`. Loops until `approve`; free-form = `revise` for this run.

## Phase 2 — Implementation (autonomous)
Deep scan/guard mechanics (resume guard, changed-repo-set, security sink lists, row-by-row test detail) → **`references/phase-2-guards.md`** — read at the step it names.
10. **Implement.** Spawn `engineer` implement mode, pass `Type`, point at `tasks.md` (the executable task list) + `spec.md` acceptance scenarios (it reads + ticks there). **`uxui-plan.md` exists** → point the engineer at it as the **UI design contract** (build each screen/state to its Scenes + wireframes, not a generic layout). INDEX → `building`; state `step=implement`. Resume guard, diff check, `FANOUT_REQUESTED: implement` → guards step 10.
11. **Test (runs before review** — reviewers judge a green suite). `phase_plan.test == "skip"` → one-line `tests.md` stub, record `skipped_steps`, → 12. Else feat/refactor/fix → spawn `qa` execute mode (pass `test-plan.md` + `e2e_visual`; **tiered — Impacted inner loop, full suite deferred to the final gate 13a**), INDEX → `testing`, state `step=test, next_step=review`; failing → `cycles.test++`, route to `engineer` then re-enter test while `cycles.test` < 3, ≥3 → escalate. chore/docs → `tests.md > Skipped` stub yourself (`next_step=review`); spike → skip test entirely (`recommendations.md` is the deliverable). Detail → guards step 11.
12. **Review.** `phase_plan.review == "skip"` (or chore/docs at XS with `review != "run"`) → record `skipped_steps`, → 13. Else compute the **changed-repo set**, spawn `lead` review mode (model `sonnet` default; keep opus for `Size=L` / `## API/event contracts` / test-**infra**), INDEX → `review`, state `step=review, next_step=security`. **Dedup:** pass step-11 `tests.md` coverage so the review test-coverage lens folds it in. Multi-repo → surface fanout (`references/surface-fanout.md`); `FANOUT_REQUESTED: review` → tiered workers. Verdict `fix-required` + `cycles.review` < 2 → `cycles.review++`, route to `engineer`, then **re-enter test (11) targeted** before re-review; ≥2 → escalate. Detail → guards step 12.
13. **Security (trigger-based).** Scan every changed repo by path category + content-pattern sink (also on user request); any sensitive path → set `security_triggered=true`, spawn `lead` security mode (multi-repo → surface fanout). `fix-required` `high` → blocking: `cycles.review++` (>2 escalate), route to `engineer`, then **re-enter test (11) targeted → review (12) → security (13)**; `medium`/`low` → append `FOLLOWUPS.md > Open` (`F-<run-id>-NN`, `security`, `path:line`), proceed to docs. Sinks → guards step 13.
13a. **Final full-suite gate** (feat/refactor/fix; pre-docs). Review + security clean → run **Full-suite** cmd from `tests.md > Commands` once via Bash (no `qa` re-spawn) = authoritative ship-blocking `passing`; inner loops (11/12/13) ran **Impacted** only. Green → `final gate: green` → docs. Red → `cycles.test++` (≥3 escalate) → `engineer` → re-enter 11 targeted. Skipped / no test surface → no gate. Detail → guards `Final full-suite gate`.
14. **Docs touch-up.** `phase_plan.docs == "skip"` or `spike` → skip (record `skipped_steps`). Else spawn `engineer` docs mode (light for fix/refactor/chore — pass the hint).
15. **Ship.** Spawn `engineer` ship mode, pass `commit_on_ship` + `open_pr_on_ship`. `=yes` → stages, commits (run ID + goal), optional PR, returns SHA + PR URL. `=no` (default) → **no commit/push/PR**, returns the run's files + a ready-to-run commit command (fix/refactor already committed → existing SHA(s) + push command); `commit_sha=null`. **Ship check** (skip if `repo_root` null): commit=yes → SHA else re-spawn; =no → command present. **CI check (PR only):** probe MCP / PR subscription / `gh pr checks`; failure → `engineer` (bumps `cycles.test`); none → `ci: unchecked` in notes.
16. **Retro.** **Stamp `done_at=<ISO>` first**, then spawn `retro`. INDEX → `done` + finished date; state `step=retro, next_step=skill-handoff`. Multi-repo → pass the changed-repo set (single multi-repo-aware pass, no fanout).
17. **Skill-candidate handoff.** Per candidate `retro` surfaced, `AskUserQuestion` whether to create; approved → invoke `skill-creator` with its handoff prompt; record outcomes. Memory candidates saved per the standard protocol, not gated here.
18. **Done.** Print summary: artifacts, files changed, commit, PR, open follow-ups, skills created. State `phase=done, step=done`.

## Fanout dispatch
Full consumer contract — the 6 `FANOUT_REQUESTED:` shapes + per-step fanout table, one-message dispatch, **Registry preflight**, **re-spawn for synthesis** → **`references/fanout.md`** (read only on a `FANOUT_REQUESTED:` return or changed-repo set > 1); **implement** consumer contract → `references/implement-fanout.md > Orchestrator consumer contract`; **Surface (per-repo) fanout** → `references/surface-fanout.md`. **First-line recognition** after every return: `FANOUT_REQ…` (case-insensitive) → that reference; `BLOCKER:` → `AskUserQuestion`; `SIZE_UPGRADE:` / `FIELD_UPGRADE:` → `Size-aware execution`; else success. Return checks fire at most one corrective re-spawn, then escalate. **Cycle escalation:** review max 2, test max 3, independent, bump **only on a real fix-routing** (`cycles.test` = failing test → `engineer`; `cycles.review` = review/security fix → `engineer`); a review/security fix re-enters test (11) **targeted** before re-review and that re-validation does **not** bump `cycles.test` unless it itself fails; the **final full-suite gate (13a)** is the one authoritative full-suite run and bumps `cycles.test` only if it goes red. At the limit → `AskUserQuestion` (continue / hand off / abort); never silently iterate past limits or downgrade severity.

## Rules
- Never invent requirements; ambiguity → `AskUserQuestion` (≤4/batch, ≤3 narrowing batches). **Never skip the interview** (step 6, every fresh run). Never *silently* skip a matrix-`✓` phase — the only sanctioned skip is a gate-confirmed deviation on a discretionary phase (5 Test / 6 Review / 8 Docs), recorded in `phase_plan` + `skipped_steps`; the protected set (interview, plan, gate, security-trigger, retro) is never skippable. The gate is non-negotiable. **Never spawn an `orchestrator` sub-agent and never fall back to `general-purpose`** — file-writing → `pm`/`lead`/`engineer`/`qa`/`retro`, fanout → `team-*`; the mode hint goes in the prompt, not the description. Keep user-facing text to one-sentence status updates (which phase, which agent, what's next) — exceptions: the gate summary, interview batch, final summary.
