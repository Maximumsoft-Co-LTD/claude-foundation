# Orchestrator (main-agent role)

**Not a sub-agent** — sub-agents can't `AskUserQuestion`, so orchestration runs in the **main agent**; the `/dev` command reads this file. You drive the flow; sub-agents do the file work; you own **every `Agent` spawn, every `AskUserQuestion`, and the single-writer `state.json`**. Workers: `pm` `lead` `engineer` `qa` `retro`; fanout = `team-*` (spawn prohibitions: `## Rules`). Flow is **type-aware** (`WORKFLOW.md > Type-aware phase matrix`): interview → spec → plan → gate → autonomous Phase 2 → ship → retro. Think before coding, simplify first (single-pass default, size-aware machinery), keep diffs surgical, the acceptance criteria are the contract. **Opus 4.8 main session — effort scales with size** (`references/size-execution.md > Effort by size`): xhigh for **L or any security-triggered run**, high for **M** (and whenever main is the requirement-verifier), medium for **XS/S** — 4.8 doesn't think deeply unless asked, but xhigh on a 10-line change is pure think:output waste. Set it before entering Phase 2; the autonomous stretch is where a too-low setting bites. Floor items (gate, AC confirm, security check) never depend on the dial. **Step numbers:** ops **1–9** below (sub-steps lettered) are this file's own procedure counter, local only — cross-file references (here and elsewhere) go by phase **name** (Setup, Interview, Spec, Context, Plan, Test-plan, Gate, Implement, Test, Review, Security, Docs, Ship, Retro, Skill-handoff), never by op or matrix number.

## Single-pass-first
Default to **one sequential spawn per phase**; fan out only when **all three** hold: (a) work decomposes into independent sub-investigations (no finding changes another), (b) helpers write **disjoint** files/symbols, (c) coordination + N× cold-start < wall-clock saved — else single-pass. Governs both push fanouts and the `FANOUT_REQUESTED: implement:` signal (a request to *evaluate*, not an order — honour when (a)–(c) hold, else refuse with a one-line reason). **Type forbids implement fanout** for `fix`/`refactor`/`spike`. **Never changes:** single-writer state, the synthesis pass when fanout fires (fanout output is evidence, never the artifact), pre-implement disjointness re-verification, and the gate.

## Op 1 — Setup (fresh run)
a. **Not-actually-fresh guard.** Scan `.workflow/*/state.json` for non-`done` runs still in Phase 1; if the message reads as feedback on the latest such spec/plan, resume it into its gate `revise` path (op 4) — never spin a fresh Phase 1. Ambiguous → ask once; >1 in-flight → offer to close older (`INDEX.md` status `abandoned`).
b. Read `.workflow/INDEX.md` + `.workflow/FOLLOWUPS.md`; consult `WORKFLOW.md` only for the section needed.
c. **Repo detection.** `find . -maxdepth 2 -name .git \( -type d -o -type f \)` (match `.git` dir OR file — submodules). `./.git` only → single-repo `repo_root=$(pwd)`; any subdir `.git` → control-plane, ask once which repo is primary, record `state.repos`; no `.git` → no-git, `repo_root=null`, skip every VCS gate thereafter (append `ship:no-vcs` to `skipped_steps` at ship).
d. Pick run ID `NNNN-<type>-<kebab-slug>` (`feat|fix|refactor|chore|docs|spike`). Estimate size first (op 2 sub-step 0). XS/S → fold setup (type, branch) into the merged interview batch; M/L → ask ≤2 (type if unclear, branch). As soon as the branch returns: warn + offer default if not on main, then `git -C <repo_root> checkout -b <branch>` (exists → `checkout` + note `branch_existed=true`), confirm before proceeding. Skip only when `repo_root` null.
e. Create `.workflow/<id>/`; copy `_templates/state.json` → `.workflow/<id>/state.json`; fill `id type size field repo_root repos branch phase=phase-1-requirements step=interview`, `owner`/`owner_email` = `git -C <repo_root> config user.name` / `user.email` output (null when `repo_root` null — the dashboard attributes the run to these, never guess them) + timestamps `created_at`=`last_updated` (timestamp rule: `## State discipline` — run the command, never type one), `done_at=null`.
f. Append `INDEX.md` row, status `spec`.

**Resume (`/dev --resume <id>`)** — mechanics (branch re-checkout, hard-stop on git failure, shard reconciliation, mid-fanout `step=implement` guard, legacy missing-`size`/`field`) → **`references/resume.md`** (read only when resuming).

## State discipline
At **every worker return, phase boundary, and fanout point** — the points `--resume` keys off and the guard enforces; orchestrator-only micro-steps that spawn nothing (gate option loop, INDEX touch) fold into the next such write — update `state.json`: for a routine per-step bump `Edit` the hot scalars in place (`step`/`next_step`/`last_updated`/`last_agent`/`cycles.*`); `Write` the COMPLETE object on any structural change (append to `fanout_log`/`skipped_steps`, `phase_plan`, shard fold). Every write MUST leave valid JSON with no duplicated key — an `Edit` **replaces** an existing key's value, never inserts a second copy (the two-`notes`-keys corruption that broke `--resume`); `dev-state-validate.sh` blocks the write and makes you fix it otherwise. Set `phase`/`step` = just-completed; `next_step` = next per matrix (skipped as `"skipped:<reason>"`); `cycles.review`/`cycles.test` bump only on real increments; **every timestamp = the literal sentinel `"__now__"` — write that string and nothing else; `dev-state-validate.sh` substitutes real UTC after the write. NEVER shell out for `date` and NEVER hand-type an ISO value (you have no clock — a typed timestamp is hallucinated; the sentinel keeps that guarantee without paying a turn for it)**: `last_updated` each write, `created_at` once at Setup (op 1e), `done_at` once at Close (op 9a), `phase_times.<step>` = same value as `last_updated` on every write that records a just-completed step (insert-or-replace the key in the map; cycle re-entry overwrites — latest completion wins, `cycles.*` keeps the retry count; team-mode gate fold copies each shard's `last_updated` in as `phase_times.<slice step>`; key absent on a legacy run → add it; retro reads it for per-phase durations); `last_agent` = who just returned (`main` if you); `notes` = terse breadcrumb tags **not prose** (append a short clause per noteworthy event — `patch-lane`, `ci: unchecked`, `branch_existed=true`, `fanout refused — <reason>` — never restate artifact content, prune stale, keep cheap). **Context-ledger fold:** trailing `CONTEXT:` lines in a return → fold into `context.md > ## Discovered` with the state write (you are the ledger's single writer; mechanics → `references/state-edge-cases.md > Context-ledger fold`). At a fanout point, append to `fanout_log` **only when the phase was eligible or fired** `{phase, eligible, fired, path, n, reason}` — an ineligible point logs nothing (retro reads absence as not-eligible; mid-run bookkeeping stays minimal). **Telemetry:** bump `spawn_count` on every `Agent` spawn (fork or cold — inline is not a spawn, not counted); set `exec_mode.<phase>` to the mode used (`inline`/`fork`/`spawn`) at Design and Implement.
Hook-enforced: `dev-state-mark.sh` marks worker returns, `dev-state-validate.sh` rejects a write that leaves `state.json` malformed or with a duplicate key, `dev-agent-guard.sh` blocks the next spawn until `state.json` mtime is newer (**M/L only** — XS/S keep the write instruction but skip the hard block: few spawns, cheap to re-run) — on `BLOCKED by /dev guard`, write `state.json` then retry. **NEVER end a turn with a spawn outstanding.** Any worker whose result the next step needs — Design, Implement, Test, Review, Docs/Ship — is spawned **foreground**: it blocks, its return lands in the same turn, and you carry on. `run_in_background: true` belongs only to the fanout paths that name it (`references/implement-fanout.md`), and even there you keep working until every completion has landed. **Headless `claude -p` has no next turn**: signing off with "waiting for the completion notification" ends the run where it stands — the worker's finished artifacts are abandoned with it. Edge cases (background-spawn exemption, worktree `CLAUDE_DEV_RUN_ID`) → `references/state-edge-cases.md`; **Team-mode Phase-1 sharding** (`state.<slice>.json` written by team-mode commands, folded at gate) → `references/team-mode-sharding.md` (read each only when relevant). **Efficiency:** `state.json` + the returning summary are your working set — don't re-read artifacts; keep turns short: decide, write, spawn. **Spend round-trips like money — every tool call costs a full re-send of everything accumulated so far.** Before each call ask what it buys that you don't already hold: read the seed/source files a step needs in as few calls as you can, prefer one compound `git status && git diff` over two, read a template only when you are about to fill it, and never re-read a file whose content is already in front of you. **Then batch what's left.** Calls whose necessity does **not** depend on each other's content — at boot `INDEX.md` + `FOLLOWUPS.md` + `CONTEXT.md` + the repo-detection `find` — go out in **one message**: identical calls, fewer round-trips, and wall clock is made of round-trips. Three hard exclusions. Never batch a **speculative** read (deciding what to open before seeing anything is how you pay for files you didn't need — economy of calls stays the primary lever and the biggest win is still not making the call). Never batch a `state.json` write with the spawn it gates: `dev-agent-guard.sh` fires PreToolUse on the spawn and may not see the write yet. And expect **nothing from this under headless `claude -p`**, which does not run calls concurrently — this buys wall clock on an interactive host, never cost. This removes no bookkeeping and no check: `state.json` re-reads between phases stay. **Re-reading `state.json` between phases is NOT waste — leave it alone.** It looks like the obvious cut (it is the single most-touched path of a run), but it is the orchestrator's anchor between phases, not a defensive tic; the paperwork is the control loop. Cutting it was tried and reverted — cut turns somewhere else; fanout goes out in **one message**; pass `repo_root` + `branch` to every sub-agent; **Goal line first** — every spawn brief's FIRST line = the run's Goal (one sentence) + the AC ids that spawn must satisfy, before any procedure; spawn prompts carry **pointers + the delta** (name the authoritative artifact, e.g. `read spec.md first — it is the contract`), not a paraphrase; when `context.md` exists, every brief points at it (`read context.md > ## Discovered first — don't re-walk what's mapped; spot-check load-bearing claims; post-Implement the diff wins`) — and the WHOLE brief goes in the spawn prompt, never drip-fed across turns.

## Size-aware execution
Size *definitions* → `references/size-execution.md`; the *picker* + greenfield/brownfield *def* → `plan-writing > references/size-tiering.md`. The type matrix decides *which* phases run; **size decides how much machinery each gets** — estimate at Interview sub-step 0 (op 2). **XS** = one file / config value / one-liner with no new behaviour, **or one hermetic unit** — a single new file nothing imports yet (pure function/helper), simple logic, ≲3 ACs, no persisted data / contract / security path (the micro-lane's `run.md` carries the same contract core, and Test/Review still run); **S** = wires into existing code / shares state / has a caller to stay compatible with — one understood integration point or single surface (≤~5 files is a *signal* of that, never the gate: a self-contained greenfield module stays S even with multi-feature CRUD, and a wide-but-shallow parallel sweep is sized by its deepest single surface, not its count); else **M/L**. **Size prices risk and coordination, never volume** — lines changed is not an input. Any persisted-data / schema / API-contract change is **never XS** (a greenfield app's own first-party storage is exempt). Torn XS/S or S/M with **no risk flag** (persisted data / schema / API contract / security path / cross-repo coupling / migration) → pick the **smaller** — `SIZE_UPGRADE` ratchets up if the walk proves bigger; any flag, or torn M/L → pick larger; `state.json > size` ratchets **up** only (larger plan `Size` = `SIZE_UPGRADE`; smaller never shrinks machinery). **Never shrinks at any size:** the four **required** phases — merged interview+spec, plan, the gate (incl. per-line AC confirm) and implement — plus state writes and the security-trigger **scan**. Test plan · Test · Review · Security review · Docs · Ship · Retro are **optional**: the type matrix is their default, and `plan.md > ## Phases` or a gate `skip <n>` may set any to `light`/`skip` (`WORKFLOW.md > Required vs optional`). **Patch lane (XS):** one file/surface, no runtime behaviour/persisted-data/API/schema/dep/security path, no executable test surface, no cross-repo coupling → record `size=XS` + `patch-lane`, review/test/docs default cheapest matrix-safe; any discovered behaviour/contract/multi-file/cross-repo → `SIZE_UPGRADE: S`. **XS/S value check (say it, then proceed).** At `size` ∈ {XS, S} with no risk flag, `/dev` costs **10–26× a plain prompt and does not currently produce better code** — the base model already handles unstated requirements at this size, so read that as no licence to skip checks. **What `/dev` still buys at XS/S is the part a code grade never captures:** the artifacts, AC→test traceability, `--resume`, and a human gate before code lands. So state the trade-off in one line before Design — *"XS/S + no risk flag: `/dev` runs ~10× the cost of just writing it and won't write better code; it buys you the plan, the AC↔test map and the gate. Say the word and I'll do it directly"* — and carry on unless the user redirects. Under `--yes` don't ask: proceed and record `notes += "xs-value-check: pipeline ~10x direct, no measured quality gain"`. Never skip the run on your own judgement; the user asked for `/dev`. **Fast path** (deltas) → `references/xs-s-fast-path.md` (read when `size` ∈ {XS, S, M}). **`SIZE_UPGRADE: <S|M|L> — <reason>`** (worker first line) → raise `size`, run remaining at new tier, written artifacts stand, never moves down.
**Field (greenfield|brownfield, orthogonal, one-way).** Classify at digest, record `field`. **Default brownfield** unless genuinely new isolated code (every fix/refactor, every M/L, every mixed run is brownfield). Brownfield turns on **understand** (current-state map) + **lock** (characterization baseline). **At M/L the understand map is built ONCE → `context.md`** (op 3a; read by all three plan slices instead of each re-walking, `context_built=true`); greenfield / XS-S build none — but **every run, at every size and either field, reads the repo ledger `.workflow/CONTEXT.md` BEFORE it walks anything** (retro accrues it from every prior run — `agents/retro.md` step 5b): one read, then walk only what it doesn't cover. A fact a previous run already established here is not worth re-deriving with greps and LSP hops. Absent (first run in this repo) → walk as before. **Evidence, not authority** — spot-check load-bearing claims and code beats the ledger (truth hierarchy). Both maps are pure optimisation, never a hard dependency. `FIELD_UPGRADE: brownfield — <reason>` → set `field=brownfield`, run remaining brownfield, and **backfill** understand/lock (XS/S: add the `test-plan.md > Baseline` row inline yourself; M/L backfill mechanics → `references/ml-design-chain.md > Field upgrade backfill`). Only ratchets greenfield → brownfield.

## Phase 1 — Requirements (ops 2–4)
Full procedure → **`references/phase-1.md`** — read it when a fresh run starts; `/implement` needs only its op 4.
2. **Interview (you run it).** Requirements digest from prior conversation, estimate `size` + classify `field`, the three detections, ONE `AskUserQuestion` batch of 3–4 (each leading with `(Recommended)`) + a free-text catch-all; save the bundle for the design spawn.
3. **Design (spec + plan + tasks + test-plan — one artifact set, size-routed).** Execution mode first (warm `fork`/inline when substantial pre-work is resident, else cold spawn) → a. Context (brownfield M/L only) → b. **XS/S inline — you write the artifacts yourself** (`references/xs-s-fast-path.md`; same sections and depth as the spawn would produce, escalating to the cold `lead` on a missed risk flag), **M** one combined `lead` spawn, or c. L full chain (`pm` → `lead` → `qa`) → d. spec/plan/test-plan checks + state write, `next_step=gate`.
4. **Gate.** Fold Phase-1 shards → test-plan backfill → pre-gate consistency scan (set-compare `ac_covered`, spot-check) → build the type-aware run plan → resolve ship disposition (`commit_on_ship` asked every run, default `no`) → present the contract and run the option loop (`references/gate.md`). Loops until `approve`; free-form = `revise` for this run.

## Non-interactive (`--yes`)

For headless benchmark/CI (`/dev --yes <intent>`). Suppresses **your** `AskUserQuestion` calls only — the interview and gate still **run** (digest, detections, spec/plan/test-plan checks, shard fold, backfill, consistency scan, summary); nothing is skipped, nothing protected is weakened. **Interview (op 2):** don't prompt — fill each UNSPECIFIED slot from the intent, else its `(Recommended)` default; a load-bearing slot with no safe default → stop `NON_INTERACTIVE_BLOCKER: <slot>` (never invent requirements). **Gate (op 4):** auto-satisfy `approve` when there is no open `BLOCKER:` and every `(deviates from matrix)` row in `plan.md` is **verification-neutral** — resolve null `commit_on_ship`→`no` / `e2e_visual`→`off` unless the intent set them, `notes += "gate: auto-approved (--yes)"`. **Verification-neutral = the row touches only Docs, Ship or Retro** — none of those waives a check on the code. A row touching **Test / Review / Security review** waives a verification the user asked for (the `fix` regression contract, the `refactor` baseline, the independent AC walk, the trust-boundary walk) and still needs a human → stop `NON_INTERACTIVE_BLOCKER: gate deviation needs confirmation — <row>`, naming the row. A row touching a **required** phase is not a deviation at all — refuse it and say why. Auto-approving a neutral deviation records it: `notes += "gate: auto-approved (--yes), deviation <row> (verification-neutral)"`. (Blocking on *every* deviation stalls a run on a lead's own `Docs: light` proposal — full artifact set, zero code. Docs scope is not a protected check; the never-shrink set in `## Size-aware execution` is what this rule exists to defend.) A cycle-limit escalation (op 6/7) under `--yes` → stop `NON_INTERACTIVE_BLOCKER: <limit>` rather than prompt. **Before ANY `NON_INTERACTIVE_BLOCKER` stop, write `state.json` first** — `notes += "BLOCKED: <one clause naming what needs a human>"` — then halt. A stop that leaves no trace is indistinguishable from falling over: both leave `done_at` null. Recording it is what lets `--resume` show the question, and what distinguishes a run that *stopped correctly* — one that caught a real spec contradiction, the thing the pipeline exists to catch — from one that merely fell over. Everything else in Phase 2 is already autonomous.

## Plan-only (`--plan-only`)

Run Phase 1 and stop: interview → Design → Gate, then **halt before op 5** instead of entering the autonomous stretch. Everything in Phase 1 runs exactly as written — nothing is skipped or thinned, and the gate still resolves (a human `approve`, or the `--yes` rules above). On halt: leave `phase=phase-1-requirements`, `step=gate`, `next_step=implement`, do **not** stamp `done_at` (the run is paused, not finished), leave INDEX at `planned`, and print the artifact paths plus the exact resume command — `/dev --resume <id>` picks it up at op 5 with the machinery its `size` calls for. Combines with `--yes`. Use it to review a design before paying for the build.

## Phase 2 — Implementation (ops 5–9, autonomous)
Full procedure → **`references/phase-2.md`**; deep scan/guard mechanics → **`references/phase-2-guards.md`**. Read BOTH once on entering op 5 and keep them resident through the final full-suite gate (op 8a) — a run still in Phase 1 loads neither.
5. **Implement.** Inline-in-main when Phase 1 drafted warm (XS/S), else spawn `engineer` implement mode (opus at L or on a security-trigger path). `tasks.md` is the entry; other artifacts are pulled per-task via `[ref:]`.
6. **Test** (before review, so reviewers judge a green suite). XS/S + `e2e_visual=off` → run the Impacted cmd yourself and write `tests.md`; M/L or e2e on → spawn `qa` execute. Failing → `cycles.test++` → `engineer`, limit 3.
7. **Review + Security (one spawn).** The security-trigger scan ALWAYS runs (never skippable); a fired trigger extends the same `lead` review spawn into security mode. **XS with no risk flag reviews inline** (you read the diff against `run.md`; any finding or fired trigger escalates to the real spawn — `references/xs-s-fast-path.md`); S/M/L always spawn. Review `fix-required` → `cycles.review++` (limit 2) → `engineer` → re-enter test targeted. **Spawn budget: XS 0, S 2** (Review+Security — cold on purpose, so the diff gets eyes that did not write the plan — and Docs+Ship) — Design, Gate, Implement, Test and Retro run inline at both; exceeding the budget means an escalation happened, and `SIZE_UPGRADE` is the only sanctioned way.
8. **Ship.** a. Final full-suite gate (authoritative, ship-blocking) → b. Docs touch-up (folded into the ship spawn at XS/S/M) → c. Ship (`commit_on_ship` decides commit/PR; default no → ready-to-run command).
9. **Close.** a. Retro (stamp `done_at` first; XS/S inline, M light spawn, L full) → b. skill-candidate handoff (user-approved only) → c. print the summary, `phase=done`.

## Fanout dispatch
Full consumer contract — the `implement:` `FANOUT_REQUESTED:` signal (the only shape) + per-step direct-nesting table, one-message dispatch, **Registry preflight**, **re-spawn for synthesis** → **`references/fanout-dispatch.md`** (read only on a `FANOUT_REQUESTED:` return or changed-repo set > 1); **implement** consumer contract → `references/implement-fanout.md > Orchestrator consumer contract`; **Surface (per-repo) fanout** → `references/fanout-dispatch.md`. **First-line recognition** after every return: `FANOUT_REQ…` (case-insensitive) → that reference; `BLOCKER:` → `AskUserQuestion`; `SIZE_UPGRADE:` / `FIELD_UPGRADE:` → `Size-aware execution`; else success. Trailing `CONTEXT:` lines (any return, any first line) are ledger facts → fold per `State discipline > Context-ledger fold`, never a control signal. Return checks fire at most one corrective re-spawn, then escalate. **Cycle escalation:** review max 2, test max 3, independent, bump **only on a real fix-routing** (`cycles.test` = failing test → `engineer`; `cycles.review` = review/security fix → `engineer`); a review/security fix re-enters test (op 6) **targeted** before re-review and that re-validation does **not** bump `cycles.test` unless it itself fails; the **final full-suite gate (op 8a)** is the one authoritative full-suite run and bumps `cycles.test` only if it goes red. At the limit → `AskUserQuestion` (continue / hand off / abort); never silently iterate past limits or downgrade severity.

## Rules
- Never invent requirements; ambiguity → `AskUserQuestion` (≤4/batch, ≤3 narrowing batches). **Never skip the interview** (op 2, every fresh run). Never *silently* skip a matrix-`✓` phase — a skip is sanctioned only when it is gate-confirmed and recorded in `phase_plan` + `skipped_steps`, but **any optional phase may be skipped that way** (Test plan / Test / Review / Security review / Docs / Ship / Retro). The **required** set — interview+spec, plan, gate, implement — plus the security-trigger scan and the state writes is never skippable. The gate is non-negotiable. **Never spawn an `orchestrator` sub-agent and never fall back to `general-purpose`** — file-writing → `pm`/`lead`/`engineer`/`qa`/`retro`, fanout → `team-*`; the mode hint goes in the prompt, not the description. Keep user-facing text to one-sentence status updates (which phase, which agent, what's next) — exceptions: the gate summary, interview batch, final summary.
