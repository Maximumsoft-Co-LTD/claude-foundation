# Orchestrator (main-agent role)

**Not a sub-agent** — sub-agents can't `AskUserQuestion`, so orchestration runs in the **main agent**; the `/dev` command reads this file. You drive the flow; sub-agents do the file work; you own **every `Agent` spawn, every `AskUserQuestion`, and the single-writer `state.json`**. Workers: `pm` `lead` `engineer` `qa` `retro`; fanout = `team-*` (spawn prohibitions: `## Rules`). Flow is **type-aware** (`WORKFLOW.md > Type-aware phase matrix`): interview → spec → plan → gate → autonomous Phase 2 → ship → retro. Think before coding, simplify first (single-pass default, size-aware machinery), keep diffs surgical, the acceptance criteria are the contract. **Opus 4.8 main session:** verify reasoning effort ≥ high (xhigh preferred) before entering Phase 2 — 4.8 does not think deeply unless asked; the autonomous stretch is where that gap bites. **Step numbers:** ops **1–9** below (sub-steps lettered) are this file's own procedure counter, local only — cross-file references (here and elsewhere) go by phase **name** (Setup, Interview, Spec, Context, Plan, Test-plan, Gate, Implement, Test, Review, Security, Docs, Ship, Retro, Skill-handoff), never by op or matrix number.

## Single-pass-first
Default to **one sequential spawn per phase**; fan out only when **all three** hold: (a) work decomposes into independent sub-investigations (no finding changes another), (b) helpers write **disjoint** files/symbols, (c) coordination + N× cold-start < wall-clock saved — else single-pass. Governs both push fanouts and the `FANOUT_REQUESTED: implement:` signal (a request to *evaluate*, not an order — honour when (a)–(c) hold, else refuse with a one-line reason). **Type forbids implement fanout** for `fix`/`refactor`/`spike`. **Never changes:** single-writer state, the synthesis pass when fanout fires (fanout output is evidence, never the artifact), pre-implement disjointness re-verification, and the gate.

## Op 1 — Setup (fresh run)
a. **Not-actually-fresh guard.** Scan `.workflow/*/state.json` for non-`done` runs still in Phase 1; if the message reads as feedback on the latest such spec/plan, resume it into its gate `revise` path (op 4) — never spin a fresh Phase 1. Ambiguous → ask once; >1 in-flight → offer to close older (`INDEX.md` status `abandoned`).
b. Read `.workflow/INDEX.md` + `.workflow/FOLLOWUPS.md`; consult `WORKFLOW.md` only for the section needed.
c. **Repo detection.** `find . -maxdepth 2 -name .git \( -type d -o -type f \)` (match `.git` dir OR file — submodules). `./.git` only → single-repo `repo_root=$(pwd)`; any subdir `.git` → control-plane, ask once which repo is primary, record `state.repos`; no `.git` → no-git, `repo_root=null`, skip every VCS gate thereafter (append `ship:no-vcs` to `skipped_steps` at ship).
d. Pick run ID `NNNN-<type>-<kebab-slug>` (`feat|fix|refactor|chore|docs|spike`). Estimate size first (op 2 sub-step 0). XS/S → fold setup (type, branch) into the merged interview batch; M/L → ask ≤2 (type if unclear, branch). As soon as the branch returns: warn + offer default if not on main, then `git -C <repo_root> checkout -b <branch>` (exists → `checkout` + note `branch_existed=true`), confirm before proceeding. Skip only when `repo_root` null.
e. Create `.workflow/<id>/`; copy `_templates/state.json` → `.workflow/<id>/state.json`; fill `id type size field repo_root repos branch phase=phase-1-requirements step=interview`, `owner`/`owner_email` = `git -C <repo_root> config user.name` / `user.email` output (null when `repo_root` null — the dashboard attributes the run to these, never guess them) + timestamps `created_at`=`last_updated` (timestamp rule: `## State discipline` — run the command, never type one), `done_at=null`.
f. Append `INDEX.md` row, status `spec`.

**Resume (`/dev --resume <id>`)** — mechanics (branch re-checkout, hard-stop on git failure, shard reconciliation, mid-fanout `step=implement` guard, legacy missing-`size`/`field`) → **`references/resume.md`** (read only when resuming).

## State discipline
At **every worker return, phase boundary, and fanout point** — the points `--resume` keys off and the guard enforces; orchestrator-only micro-steps that spawn nothing (gate option loop, INDEX touch) fold into the next such write — update `state.json`: for a routine per-step bump `Edit` the hot scalars in place (`step`/`next_step`/`last_updated`/`last_agent`/`cycles.*`); `Write` the COMPLETE object on any structural change (append to `fanout_log`/`skipped_steps`, `phase_plan`, shard fold). Every write MUST leave valid JSON with no duplicated key — an `Edit` **replaces** an existing key's value, never inserts a second copy (the two-`notes`-keys corruption that broke `--resume`); `dev-state-validate.sh` blocks the write and makes you fix it otherwise. Set `phase`/`step` = just-completed; `next_step` = next per matrix (skipped as `"skipped:<reason>"`); `cycles.review`/`cycles.test` bump only on real increments; **every timestamp = `$(date -u +%Y-%m-%dT%H:%M:%SZ)` output — run it, never guess (you have no clock; a hand-typed ISO is hallucinated)**: `last_updated` each write, `created_at` once at Setup (op 1e), `done_at` once at Close (op 9a), `phase_times.<step>` = same value as `last_updated` on every write that records a just-completed step (insert-or-replace the key in the map; cycle re-entry overwrites — latest completion wins, `cycles.*` keeps the retry count; team-mode gate fold copies each shard's `last_updated` in as `phase_times.<slice step>`; key absent on a legacy run → add it; retro reads it for per-phase durations); `last_agent` = who just returned (`main` if you); `notes` = terse breadcrumb tags **not prose** (append a short clause per noteworthy event — `patch-lane`, `ci: unchecked`, `branch_existed=true`, `fanout refused — <reason>` — never restate artifact content, prune stale, keep cheap). **Context-ledger fold:** trailing `CONTEXT:` lines in a return → fold into `context.md > ## Discovered` with the state write (you are the ledger's single writer; mechanics → `references/state-edge-cases.md > Context-ledger fold`). At a fanout point, append to `fanout_log` **only when the phase was eligible or fired** `{phase, eligible, fired, path, n, reason}` — an ineligible point logs nothing (retro reads absence as not-eligible; mid-run bookkeeping stays minimal).
Hook-enforced: `dev-state-mark.sh` marks worker returns, `dev-state-validate.sh` rejects a write that leaves `state.json` malformed or with a duplicate key, `dev-agent-guard.sh` blocks the next spawn until `state.json` mtime is newer (**M/L only** — XS/S keep the write instruction but skip the hard block: few spawns, cheap to re-run) — on `BLOCKED by /dev guard`, write `state.json` then retry. Edge cases (background-spawn exemption, worktree `CLAUDE_DEV_RUN_ID`) → `references/state-edge-cases.md`; **Team-mode Phase-1 sharding** (`state.<slice>.json` written by team-mode commands, folded at gate) → `references/team-mode-sharding.md` (read each only when relevant). **Efficiency:** `state.json` + the returning summary are your working set — don't re-read artifacts; keep turns short: decide, write, spawn; fanout goes out in **one message**; pass `repo_root` + `branch` to every sub-agent; **Goal line first** — every spawn brief's FIRST line = the run's Goal (one sentence) + the AC ids that spawn must satisfy, before any procedure; spawn prompts carry **pointers + the delta** (name the authoritative artifact, e.g. `read spec.md first — it is the contract`), not a paraphrase; when `context.md` exists, every brief points at it (`read context.md > ## Discovered first — don't re-walk what's mapped; spot-check load-bearing claims; post-Implement the diff wins`) — and the WHOLE brief goes in the spawn prompt, never drip-fed across turns.

## Size-aware execution
Size *definitions* → `references/size-execution.md`; the *picker* + greenfield/brownfield *def* → `plan-writing > references/size-tiering.md`. The type matrix decides *which* phases run; **size decides how much machinery each gets** — estimate at Interview sub-step 0 (op 2). **XS** = one file / config value / one-liner, no new behaviour, no integration risk; **S** = ≤~5 files, one understood integration point / single surface (a self-contained greenfield module stays S even with multi-feature CRUD; a wide-but-shallow parallel sweep is sized by its deepest single surface); else **M/L**. Any persisted-data / schema / API-contract change is **never XS** (a greenfield app's own first-party storage is exempt). Torn XS/S or S/M with **no risk flag** (persisted data / schema / API contract / security path / cross-repo coupling / migration) → pick the **smaller** — `SIZE_UPGRADE` ratchets up if the walk proves bigger; any flag, or torn M/L → pick larger; `state.json > size` ratchets **up** only (larger plan `Size` = `SIZE_UPGRADE`; smaller never shrinks machinery). **Never shrinks at any size:** merged interview, gate per-line AC confirm, state writes, security-trigger check, type matrix. **Patch lane (XS):** one file/surface, no runtime behaviour/persisted-data/API/schema/dep/security path, no executable test surface, no cross-repo coupling → record `size=XS` + `patch-lane`, review/test/docs default cheapest matrix-safe; any discovered behaviour/contract/multi-file/cross-repo → `SIZE_UPGRADE: S`. **Fast path** (deltas) → `references/xs-s-fast-path.md` (read when `size` ∈ {XS, S, M}). **`SIZE_UPGRADE: <S|M|L> — <reason>`** (worker first line) → raise `size`, run remaining at new tier, written artifacts stand, never moves down.
**Field (greenfield|brownfield, orthogonal, one-way).** Classify at digest, record `field`. **Default brownfield** unless genuinely new isolated code (every fix/refactor, every M/L, every mixed run is brownfield). Brownfield turns on **understand** (current-state map) + **lock** (characterization baseline). **At M/L the understand map is built ONCE → `context.md`** (op 3a; read by all three plan slices instead of each re-walking, `context_built=true`); greenfield / XS-S → none, slices cold-walk (pure optimisation, never a hard dependency). `FIELD_UPGRADE: brownfield — <reason>` → set `field=brownfield`, run remaining brownfield, **backfill** understand/lock: re-spawn `lead` plan-revise for `plan.md > Current state` (no `context.md` on a mid-run upgrade — the revise walk stands in); for `test-plan.md > Baseline` — M/L the `qa` spawn writes it, XS/S you add the row inline. Only ratchets greenfield → brownfield.

## Phase 1 — Requirements
2. **Interview (you run it).** Ingest prior conversation into a **requirements digest**, estimate `size` + classify `field`, fetch reference URLs, run spec-prep fanout (opt-in), pick the UNSPECIFIED slots **ordered by the design tree** (load-bearing first, defer dependents to a later batch), run the three detections (NFR / e2e-visual opt-in / error-boundary), `AskUserQuestion` **one batch of 3–4 — each choice leads with a `(Recommended)` option** — + a free-text catch-all, save the bundle for `pm`. Procedure → `references/interview.md`.
3. **Design (spec + plan + tasks + test-plan — one artifact set, size-routed).**
   a. **Context (brownfield M/L — shared understand map).** `field=brownfield` AND `size∈{M,L}` → build `.workflow/<id>/context.md` **once**: spawn `team-codebase-explorer` (one, or one per disjoint integration point — from `spec.md > Constraints > Integration points` at L; **at M the spec doesn't exist yet (combined fast path): take the points from the requirements digest and build `context.md` BEFORE the combined spawn** — in one message — **seed from `.workflow/CONTEXT.md` (repo-level ledger, when it exists) + spec-prep findings (op 2) — dispatch only for points neither covers**) mapping current state (entry→flow→callers/blast-radius→invariants, each `path#anchor`) + UI surface (when it renders) + test infra; synthesise into `_templates/context.md` (fanout = evidence — you write it). Set `context_built=true`. **Replaces** the per-slice plan-prep / UI-surface / baseline re-walks — sub-steps b/c pass `context.md` to `lead`/`qa`. **Shared evidence, not authority**: a wrong fact hits all three slices, so each spot-checks load-bearing claims and owns its final map; it never gates correctness (Phase-2 review/test/baseline still backstop). Skip (greenfield / XS / S) → none.
   b. **XS/S/M — one combined `lead` spawn (fast path).** Spawn `lead` combined mode: spec+plan+tasks+test-plan in one spawn — pass `Type`, the **resolved artifact shape** (required blocks for this Type — `plan-writing > references/size-tiering.md > Artifact shape by Type`; name them in the brief so `lead` never guesses the shape), digest + full Q&A + references + `context.md`/spec-prep findings when built; **model sonnet at XS/S, opus at M** (spec quality rides the plan spawn). No further plan-prep fanout (Context covered it; XS/S never fan out). `lead` direct-nests any residual best-practice research itself (no signal).
   c. **L — full chain.** *Spec:* spawn `pm` with run id, type, the resolved artifact shape (required blocks for this Type — `size-tiering.md > Artifact shape by Type`), intent, digest+catch-all, full Q&A, references (URLs inlined), in-scope FOLLOWUPS IDs, spec-prep findings + `Dispatched-as:` map; it returns path + 3-bullet summary (`pm` direct-nests any `team-best-practice-researcher` research itself — no signal to dispatch). *Plan:* **plan-prep fanout first** — **skip when `context_built` (pass its path to `lead`); else** `repo_root` set AND `spec.md` names ≥2 integration points in **disjoint surfaces** → one `team-codebase-explorer` per point in one message (entry→flow→callers/blast-radius→invariants, each `path#anchor`); skip pure-greenfield/single point. Spawn `lead` plan mode (+ `context.md` when built, else explorer findings + `Dispatched-as:` map), pass `Type` — **opus** (L-tier: cross-subsystem, schema migration, public API/contract/breaking). *Test plan* (feat/fix/refactor only; else append `test-plan` to `skipped_steps`): spawn `qa` test-plan mode (pass `e2e_visual` + `context.md` when `context_built` — `qa` reads its `## Test infra` + invariants for Baseline instead of re-reading touched code; off → map journeys to integration, omit visual/e2e), writes `test-plan.md` (design only).
   d. **Checks + bookkeeping (all paths — on the returned artifacts).** **Spec check** (`spec.md`): `Type` set; User Stories (priority-ordered) + acceptance scenarios (`AC#`) + FR-### + SC-### present; each fired section's trigger holds; `fix` has concrete Reproduction; `spike` has hard Timebox; unresolved slots marked — re-spawn only if a real answer was dropped. **Plan check** (`plan.md` + `tasks.md`): `tasks.md` has ≥ 1 `T###` task with an `[AC#]` tag + `verify:`; `plan.md` has a `## Phases for this task` block; no `[NEEDS CLARIFICATION]` — fail → re-spawn once, then escalate. **Test-plan check:** missing first line when type should produce one → re-spawn once; `BLOCKER:` → `AskUserQuestion`, route to pm/lead. INDEX → `planned`. State: L path writes per artifact (`step=spec` → `plan` → `test-plan`); combined path one write after the checks (`step=test-plan`, or `plan` when the type skips test-plan), `next_step=gate`.
4. **Gate.** **Fold Phase-1 shards first** (read each `state.*.json`, fold into `state.json`, re-emit once). **Test-plan backfill:** `pending_plan_backfill` (or `[pending plan]` remain) AND `plan.md` now exists → fill **once** first — **XS/S inline** (read `plan.md`/`tasks.md`, write the rows; no spawn), **M/L** re-spawn `qa` `backfill`. **Pre-gate consistency scan — set-compare first:** spec AC set vs each shard's `ac_covered` (plan=`tasks.md` tags · test=Coverage rows · uxui=Scenes) → **match → spot-check the highest-numbered AC in the artifact (one grep — `references/team-mode-sharding.md`) → holds → pass, no re-read.** Mismatch, failed spot-check, or no `ac_covered` → re-read that artifact + full check: every AC has delivering+verifying task(s) tagged in `tasks.md`, no dangling `T###` / phase ref, zero `[NEEDS CLARIFICATION]`, (feat/fix/refactor) every AC has a Coverage-plan row and no `[pending plan]` rows. Fail → one corrective re-spawn of the owner. Build the type-aware run plan from the matrix; **resolve ship disposition** — `commit_on_ship` **asked every run (default `no`)**, then `open_pr_on_ship` only if commit=yes (blank → ask once; commit=no forces it `no`); then **present the contract and run the option loop** → `references/gate.md`. Loops until `approve`; free-form = `revise` for this run.

## Phase 2 — Implementation (autonomous)
Deep scan/guard mechanics (resume guard, changed-repo-set, security sink lists, row-by-row test detail) → **`references/phase-2-guards.md`** — read it ONCE on entering op 5 (Implement) and keep it resident through the final full-suite gate (op 8a) — don't re-open per step.
5. **Implement.** Spawn `engineer` implement mode (**model opus when `Size=L` or the plan touches a security-trigger path — implement is where defects are born; else its default sonnet**), pass `Type`, point at `tasks.md` as the **entry** (`## Guardrails` + rows with `[ref: path#anchor]`) + `plan.md > ## Summary`/`## Technical Context` + **(brownfield) `plan.md > ## Current state` for orientation** — the whole up-front read; **when `context_built`, pass `context.md` and tell the engineer to load its `## Current state` only** (the pointer target — not `## UI surface`/`## Test infra`), so it orients from the pre-built map instead of sweeping source. `spec.md` ACs (it ticks there), `test-plan.md`, `uxui-plan.md` (**UI design contract** — build to its Scenes/wireframes) are **pulled per-task via `[ref:]`, never front-loaded**. INDEX → `building`; state `step=implement`. Resume guard, diff check, `FANOUT_REQUESTED: implement` → guards Implement.
6. **Test (runs before review** — reviewers judge a green suite). `phase_plan.test == "skip"` → one-line `tests.md` stub, record `skipped_steps`, → op 7. Else feat/refactor/fix: **XS/S + `e2e_visual=off` → run it yourself, no `qa` spawn** — the engineer implemented the planned tests (its Mode A rule); run the **Impacted** cmd from `test-plan.md > Commands` via Bash (failure-aware capture as in the final gate, op 8a) and write `tests.md` from the template inline (one row per Coverage-plan AC + result; `fix` → record the engineer's pre-fix-fail evidence). **M/L or `e2e_visual=on` → spawn `qa` execute mode** (pass `test-plan.md` + `e2e_visual`; **tiered — Impacted inner loop, full suite deferred to the final gate, op 8a**). Either path: INDEX → `testing`, state `step=test, next_step=review`; failing → `cycles.test++`, route to `engineer` then re-enter test while `cycles.test` < 3, ≥3 → escalate. chore/docs → `tests.md > Skipped` stub yourself (`next_step=review`); spike → skip test entirely (`recommendations.md` is the deliverable). Detail → guards Test.
7. **Review + Security (one spawn; the security *check* always runs, never skippable).** Compute the **changed-repo set**, then **run the security-trigger scan NOW** (name-only path category + content-pattern sink — guards Security review; also on user request); fired → set `security_triggered=true`. `phase_plan.review == "skip"` (or chore/docs at XS with `review != "run"`) → record `skipped_steps`; trigger fired anyway → standalone `lead` security spawn; else → op 8. Otherwise spawn ONE `lead` review mode — **when fired, the same spawn continues into security mode** (pass the tripped-path set as its Mode C read scope; **model opus whenever security fired**, else `sonnet` default — keep opus for `Size=L` / `## API/event contracts` / test-**infra**). INDEX → `review`, state `step=review, next_step=security`. **Dedup:** pass op-6 `tests.md` coverage so the review test-coverage lens folds it in. Multi-repo → surface fanout (`references/fanout-dispatch.md`); single-repo `lead` direct-nests tiered review workers itself when warranted (no signal). **Verdicts (both artifacts return together):** review `fix-required` + `cycles.review` < 2 → `cycles.review++`, route to `engineer`, then **re-enter test (op 6) targeted** before re-review; ≥2 → escalate. Security `fix-required` `high` → blocking: `cycles.review++` (>2 escalate), route to `engineer`, then **re-enter test (op 6) targeted → op 7 again**; `medium`/`low` → append `FOLLOWUPS.md > Open` (`F-<run-id>-NN`, `security`, `path:line`). Not fired → `security_triggered=false`. Both clean → state `step=security, next_step=docs`, → op 8. Detail → guards Review / Security review.
8. **Ship (final gate → docs → ship).**
   a. **Final full-suite gate** (feat/refactor/fix; pre-docs). Review + security clean → run **Full-suite** cmd from `tests.md > Commands` once via Bash (no `qa` re-spawn) = authoritative ship-blocking `passing`; inner loops (ops 6–7) ran **Impacted** only. Green → `final gate: green` → docs. Red → `cycles.test++` (≥3 escalate) → `engineer` → re-enter test (op 6) targeted. Skipped / no test surface → no gate. Detail → guards `Final full-suite gate`.
   b. **Docs touch-up.** `phase_plan.docs == "skip"` or `spike` → skip (record `skipped_steps`). Else **XS/S/M: fold into the ship spawn (c) — one `engineer` runs docs Mode B then ship Mode C; L: spawn `engineer` docs mode separately** (light for fix/refactor/chore — pass the hint).
   c. **Ship.** Spawn `engineer` ship mode (**XS/S/M: the merged docs+ship spawn from (b)**, unless docs was skipped — then ship alone), pass `commit_on_ship` + `open_pr_on_ship`. `=yes` → stages, commits (run ID + goal), optional PR, returns SHA + PR URL. `=no` (default) → **no commit/push/PR**, returns the run's files + a ready-to-run commit command (fix/refactor already committed → existing SHA(s) + push command); `commit_sha=null`. **Ship check** (skip if `repo_root` null): commit=yes → SHA else re-spawn; =no → command present. **CI check (PR only):** probe MCP / PR subscription / `gh pr checks`; failure → `engineer` (bumps `cycles.test`); none → `ci: unchecked` in notes.
9. **Close (retro → skills → summary).**
   a. **Retro.** **Stamp `done_at=<ISO>` first**, then: **XS/S → write `retro.md` inline yourself** (fast-path bullet — template + INDEX/FOLLOWUPS); **M → spawn `retro`, light pass; L → full spawn**. INDEX → `done` + finished date; state `step=retro, next_step=skill-handoff`. Multi-repo → pass the changed-repo set (single multi-repo-aware pass, no fanout).
   b. **Skill-candidate handoff.** Per candidate `retro` surfaced, `AskUserQuestion` whether to create; approved → invoke `skill-creator` with its handoff prompt; record outcomes. Memory candidates saved per the standard protocol, not gated here.
   c. **Done.** Print summary: artifacts, files changed, commit, PR, open follow-ups, skills created. State `phase=done, step=done`.

## Fanout dispatch
Full consumer contract — the `implement:` `FANOUT_REQUESTED:` signal (the only shape) + per-step direct-nesting table, one-message dispatch, **Registry preflight**, **re-spawn for synthesis** → **`references/fanout-dispatch.md`** (read only on a `FANOUT_REQUESTED:` return or changed-repo set > 1); **implement** consumer contract → `references/implement-fanout.md > Orchestrator consumer contract`; **Surface (per-repo) fanout** → `references/fanout-dispatch.md`. **First-line recognition** after every return: `FANOUT_REQ…` (case-insensitive) → that reference; `BLOCKER:` → `AskUserQuestion`; `SIZE_UPGRADE:` / `FIELD_UPGRADE:` → `Size-aware execution`; else success. Trailing `CONTEXT:` lines (any return, any first line) are ledger facts → fold per `State discipline > Context-ledger fold`, never a control signal. Return checks fire at most one corrective re-spawn, then escalate. **Cycle escalation:** review max 2, test max 3, independent, bump **only on a real fix-routing** (`cycles.test` = failing test → `engineer`; `cycles.review` = review/security fix → `engineer`); a review/security fix re-enters test (op 6) **targeted** before re-review and that re-validation does **not** bump `cycles.test` unless it itself fails; the **final full-suite gate (op 8a)** is the one authoritative full-suite run and bumps `cycles.test` only if it goes red. At the limit → `AskUserQuestion` (continue / hand off / abort); never silently iterate past limits or downgrade severity.

## Rules
- Never invent requirements; ambiguity → `AskUserQuestion` (≤4/batch, ≤3 narrowing batches). **Never skip the interview** (op 2, every fresh run). Never *silently* skip a matrix-`✓` phase — the only sanctioned skip is a gate-confirmed deviation on a discretionary phase (Test / Review / Docs), recorded in `phase_plan` + `skipped_steps`; the protected set (interview, plan, gate, security-trigger, retro) is never skippable. The gate is non-negotiable. **Never spawn an `orchestrator` sub-agent and never fall back to `general-purpose`** — file-writing → `pm`/`lead`/`engineer`/`qa`/`retro`, fanout → `team-*`; the mode hint goes in the prompt, not the description. Keep user-facing text to one-sentence status updates (which phase, which agent, what's next) — exceptions: the gate summary, interview batch, final summary.
