# Foundation deterministic tests

**Audience:** Change Loop maintainers and coding agents working in this upstream
repository. This suite is not installed into consumer projects and is not a
user's checklist for proving their application.

These tests verify the shipped OpenSpec-native control plane. They do not spend
model tokens and do not test an application generated by Foundation.

## Choose a starting point

| What you are doing | Check |
|---|---|
| Repairing one behavior | Run the nearest existing regression; find its owner in [Current suites](#current-suites) |
| Finishing a related batch of edits | Inspect `run-all.sh --affected --list`, then run `run-all.sh --affected` |
| Preparing the final change for commit | Run the full `run-all.sh` gate |
| Editing documentation | Run `docs/run-doc-consistency.sh`; build `website/docs` if site pages changed |
| Investigating a timeout | Read the failing suite output and duration; use `FOUNDATION_TEST_JOBS=1` to isolate concurrency effects |

Run commands from the repository root, with the required `rtk` prefix:

```sh
rtk test bash .claude/tests/run-all.sh --affected --list
rtk test bash .claude/tests/run-all.sh --affected
# Final deterministic gate:
rtk test bash .claude/tests/run-all.sh
```

The documentation suite also runs `docs/documentation-governance.test.mjs`:
entry-guide links and fragments, first-run reading budgets, complete website
locale pairing, and the pointers to the canonical
[documentation policy](../../CLAUDE.md#documentation-ownership).
These structural checks complement semantic review; they cannot establish that
every explanation is correct or that a translation preserves its meaning.

## Setup and execution

The entrypoint is also run by `.github/workflows/workflow-tests.yml`.

Run `npm ci --ignore-scripts` in the test workspace before the full suite.
When the benchmark suite is selected, the runner checks for `c8` before launching
suites, so a missing dependency fails during setup instead of after a long run.

For an edit/repair loop, `run-all.sh --affected` selects the suites that own
the changed files plus their proof, review, Land, and mutation dependencies.
With no changed files it exits without running a suite. Use
`run-all.sh --affected --list` to inspect the selection without executing it;
the two flags may appear in either order. The selector reads added, modified,
renamed, deleted, staged, unstaged, and untracked paths; set
`FOUNDATION_TEST_BASE=<ref>` to include committed changes since a branch point.
It is deliberately conservative: changes to the composition root, protocol,
runtime version, CLI router, workspace policy, or shared test libraries expand
to the full suite set. Plain `run-all.sh` remains the authoritative final/CI
gate, so affected execution cannot silently weaken Land evidence.

Suites run concurrently — each builds its own fixture under `mktemp -d`, so
nothing orders them — and their output is buffered and replayed in table order,
so a parallel run reads and diffs exactly like a serial one. Mutation suites use
`lib/mutation-fixture.sh` to copy the runtime and detector into private source
trees before injecting faults. They therefore run in the same pool without
exposing the checkout or another suite to a mutant, and interrupted or
overlapping runs remove only their temporary trees. Set `FOUNDATION_TEST_JOBS=1`
to force fully serial execution when bisecting.
The default watchdog is 300 seconds per suite, 600 seconds for the long
suites (the real-Git pull request delivery suite, the proof loop, apply
conflict, concurrent repositories, and the installer suite, about two minutes
alone and over five on a loaded CI runner), and 1200 seconds for the combined
topology/planning fixture (about 100 seconds alone, but only 110 of its 163
assertions in 600 seconds on the macOS CI runner).
`FOUNDATION_SUITE_TIMEOUT_SECONDS` overrides all of them. A suite the watchdog
kills always counts as failed and is reported as `(timed out after Ns)` in the
failure list and the tail header; the kill stops the tree child first, so the
suite's own last assertions and summary can otherwise read like an ordinary
failure.

## Evidence views

Three wrappers restate suites above as TAP so a provider can check a discovered
count against a `minimum` floor. They are deliberately absent from `run-all.sh`,
which needs only an exit code — running them there would execute the same
assertions twice.

| Wrapper | Restates |
|---|---|
| `harness/run-changeloop-seam-tap.sh` | Change-loop seams, phase mutation guard, workspace surface, context budgets |
| `harness/run-review-gate-tap.sh` | Review and acceptance protocol, provenance, waiver policy, attempt-chain integrity |
| `harness/run-sandbox-seam-tap.sh` | Shared contract slices (sandbox creation and setup, apply, Land, multi-repository) plus the wiring contract |
| `docs/run-docs-tap.sh` | Documentation contracts and context budgets |

A wrapper adds no assertions of its own. Add the assertion to the underlying
suite, where a human reading `run-all.sh` output will also see it.

Historical phase-orchestrator fixtures remain under `bench/`, `docs/`,
`interview/`, `ledger/`, and `scenarios/` for research and migration analysis.
They are not the acceptance suite for the OpenSpec-native runtime and must not
be packaged as live hook self-tests.

## Add a regression

`user-decisions.test.mjs` runs with advance lifecycle outcomes and covers spec
approval, shared review deadlines, explicit decision routes, and waiver expiry;
`target-edits.test.mjs` beside it covers target-checkout edits made outside
the sandbox while shell mutations are audited, `session-lease.test.mjs`
covers the harness-held lease for a session Build task, and
`task-change.test.mjs` covers why a task with no change in its paths is handed
back and the routes it names.

Put a regression at the lowest deterministic boundary that caught the defect:

- runtime or evidence semantics → `harness/run-harness-tests.sh`;
- install/upgrade/CLI semantics → `harness/run-installer-tests.sh`;
- shipped hook behavior → `hooks/run-hook-tests.sh`.

Run focused checks during repair and the full `run-all.sh` gate before handing
off a harness change. See [Choose a starting point](#choose-a-starting-point).
