# Orchestrator reference — Phase 1 (Requirements)

> Loaded on demand by the main agent (`.claude/orchestrator.md`). Ops **2–4**: Interview →
> Design → Gate. Read it when a fresh run starts. **`/implement` needs only op 4** (the
> gate) — the run it resumes already has its spec/plan; skip ops 2–3.

2. **Interview (you run it).** Ingest prior conversation into a **requirements digest**, estimate `size` + classify `field`, fetch reference URLs, run spec-prep fanout (opt-in), pick the UNSPECIFIED slots **ordered by the design tree** (load-bearing first, defer dependents to a later batch), run the three detections (NFR / e2e-visual opt-in / error-boundary), `AskUserQuestion` **one batch of 3–4 — each choice leads with a `(Recommended)` option** — + a free-text catch-all, save the bundle for `pm`. Procedure → `references/interview.md`.
3. **Design (spec + plan + tasks + test-plan — one artifact set, resolver-routed).**
   **Execution resolver first** (`references/size-execution.md > Execution mode`): substantial interview/POC/code-map context resident → inline or Phase-1 `fork`; no cold hand-off. Cold-spawn only with a named proof (independent requirement slice, material code-map gap, tooling isolation, proven parallel payoff). Record both `exec_mode.design` and `exec_reason.design`.
   **Inline author contract:** read the four templates, not `pm`/`lead`/`qa` agent prompts. Spec: one-sentence Goal, Type-required shape, prioritized independently-testable stories, stable Given/When/Then ACs with reachable boundaries, and one `[evidence:<class>]` per AC; write ACs by observable outcome, not one per control/DOM node. More than 3 ACs at XS, 8 at S, or 15 at M requires an `AC_DENSITY_JUSTIFICATION:` note or a capability split. Plan: scoped current state for brownfield, approach/why, architecture, triggered risks/rollback/contracts, M/L Scaffold, phase/fanout dispositions. Tasks: dependency order, exact paths/anchors, brownfield Guardrails, one delivering+verifying row per AC. Test plan: one row per AC/boundary with the same evidence class, owning level/assertion, and an execution contract for Full+Impacted+rendered smoke including cwd/env/dependencies/expected groups or minimum tests. Strip template teaching notes and unused sections. Read one targeted `plan-writing` reference only when a triggered section remains unclear.
   a. **Context (brownfield M/L — shared understand map).** Read `.workflow/CONTEXT.md` first. If it plus a bounded main-agent walk resolves the touched entrypoints, callers, invariants and test runner, main writes `context.md` inline (`exec_reason.context=ledger+bounded-walk`). Spawn `team-codebase-explorer` only when unknown entrypoints span multiple surfaces or the map is itself an independent substantial investigation (`exec_reason.context=material-context-gap`). Set `context_built=true` either way and reuse it downstream. Procedure → **`references/ml-design-chain.md > Context`**. Greenfield / XS / S build no run-local map.
   b. **XS/S inline. M resolver-routed.**
      **XS/S:** write the resolved Type shape yourself (XS: `run.md`; S: four files) using the inline author contract. Main already holds the digest, Q&A, intent, and size/field call. Escalate on a missed persisted-data/schema/public-contract/trust-boundary/cross-repo risk; that is `SIZE_UPGRADE: M`. Record `exec_mode.design=inline`.
      **M:** interview + context map warm and one coherent design tree → main/fork writes the combined artifact set. Use one `lead` combined spawn only when a material context gap remains or an isolated design pass is justified; pass digest + full Q&A + `context.md`, and record the proof. No prep fanout after Context.
   c. **L — combined by default, full chain by proof.** A coherent capability with settled requirements uses the same single combined executor as M (inline/fork when warm, otherwise one `lead`). Use `pm → lead → qa` only when the spec, architecture and test contract are independent substantial slices whose findings do not depend on one another; record one reason per spawn. A separate `qa` is not justified merely because the artifact is a test plan. Full-chain brief contents → **`references/ml-design-chain.md > L full chain`**.
   d. **Semantic self-review + bookkeeping (all paths).** The author checks requirement meaning, architecture fit, reversibility, reachable boundaries, and runner feasibility once; do not manually recount sections or AC sets. Resolve any known `[pending plan]` row inline. Then run the deterministic Contract Gate: `sh .claude/hooks/artifact-lint.sh --contract .workflow/<id>/`. It owns required artifacts, placeholders, unresolved markers, and exact spec↔tasks↔test-plan↔UX AC sets. A structural failure → edit only the named artifact and rerun once; a semantic `BLOCKER:` → `AskUserQuestion`. INDEX → `planned`. State: L path writes per artifact (`step=spec` → `plan` → `test-plan`); combined path one write after Contract Gate (`step=test-plan`, or `plan` when the type skips test-plan), `next_step=gate`.
4. **Contract Gate.** **Fold Phase-1 shards first** (read each `state.*.json`, fold into `state.json`, re-emit once). Shard `ac_covered` is progress telemetry, never approval evidence. If a late shard/backfill changed an artifact, rerun `artifact-lint.sh --contract` once; otherwise reuse the passing result from step 3d. Build the type-aware run plan, resolve ship disposition, present the human contract and run the option loop → `references/gate.md`. Human approval validates intent and hard-to-reverse decisions; it does not repeat structural checks.
