### Implement (details)

- **Resume guard:** `--resume` into `step=implement` with `impl_phases_done` a non-empty subset → spawn the **Integration variant directly** (skip the write-intersection check); else normal. Prompt hints: references present → "open every reference first"; feat/fix/refactor → "read `test-plan.md` first, build its edge cases as you implement"; `fix` → "step 1 is the failing regression test, committed before any production fix."
- Confirm every planned `T###` is completed with its task-level `verify:` result; a missing result without a blocker → re-spawn with one correction. Do not inspect or mutate spec AC checkboxes. **Diff check** (skip if `repo_root` null): `git -C <repo_root> status --porcelain` empty → re-spawn (`spike`→confirm `recommendations.md`; `fix`→confirm HEAD advanced). `FANOUT_REQUESTED: implement:<phases>` → run the 5-step consumer contract (`references/implement-fanout.md > Orchestrator consumer contract`). "needs user input" → `AskUserQuestion`, re-spawn.

### Test (details)

- **Test runs before review** so reviewers judge a green suite. Run the resolver, not a size check. Valid `.workflow/CONTEXT.md > ## Test infra > Validated commands` + existing harness + no browser runs inline at any size; reuse those commands without package-script discovery unless their owner path is missing/touched. Browser/e2e, new harness, multi-repo coordination or independent test investigation spawns `qa`. INDEX → `testing`; state → review. Compute the changed-repo set once and hold it downstream. Pass `test-plan.md` only when spawning. Failing → `cycles.test++`, route to Implement; plan contradictions and blocking edge gaps reconcile before ship.
- **Inline path (any size):** run Impacted via failure-aware capture and write `tests.md` yourself — one authoritative row per Coverage-plan AC + result, recorded (not yet run) Full/lint/type/static commands, and fix pre-fix evidence. Green Impacted + complete mapping = `impacted-passing`. On red, route the bounded failure tail to the current Implement executor.
- chore/docs → write `tests.md > Skipped` stub yourself; `next_step=review`. spike → skip entirely (`recommendations.md` is the deliverable; move to Review for the light pass).

### Review (details)

- **Reuse the changed-repo set from Test** — don't recompute; you already hold it (`state.repos` else `[repo_root]`). Single-repo → review `repo_root`. Multi-repo → surface fanout (`references/fanout-dispatch.md`). *(Fresh `--resume` into Review with no set in memory → compute it once as in Test.)*
- **Trigger scan first:** before choosing inline vs spawn, run the Security-review name-only scan (next section) on the changed-repo set; fired → `security_triggered=true` and the review spawn carries Mode C (pass the tripped-path set as its read scope) — **one spawn, two artifacts** (`review.md` + `security.md`).
- **Inline review:** mechanical/docs/config work with deterministic verification reads `_templates/review.md`, consumes Test evidence once, walks every task plus only semantic/contract risks, and writes `review.md`; size does not forbid this.
- **Independent review:** runtime-behaviour M/L or fired Security spawns one `lead`. A volume-routed Sonnet implementation also requires an independent author boundary, but at S main satisfies it inline; M/L use `lead`. Model sonnet by default, opus for Security/API/test-infra risk. Pass only changed scope + tests evidence.
- Verdict `fix-required` + `cycles.review` < 2 → `cycles.review++`, route to `engineer` with findings, capture the exact changed-since-review files/hunks, then **re-enter test targeted** (`re-validate targeted: <files>`; Impacted + AC-mapped only, no full suite). Re-review with `review_delta` = prior blockers + changed hunks + affected AC/task rows; do not resend/re-walk the full artifact set. Full re-review only if the fix changes a public contract, shared invariant, security boundary, or escapes its declared scope. ≥2 → escalate (`AskUserQuestion`, max 2). (Multi-repo non-primary blocker → surface, never auto-fix.)

### Security review (details)

**Runs BEFORE the review spawn (Review details, "Trigger scan first"). Decide the trigger from filenames — never pull the diff body into your context** (this boolean only picks whether the Review-op `lead` spawn carries security mode — the lead reads the actual code itself). Scan every changed repo two **name-only** ways: (1) `git -C <r> diff --name-only` for path-named categories (auth/session, crypto, `.env`/secret, migrations, new network clients); (2) a content pickaxe `git -C <r> diff -G'innerHTML|outerHTML|document\.write|eval|Function|dangerouslySetInnerHTML|\.html\(|exec|spawn|child_process|query\(|raw\(' --name-only` — returns only the *files* whose added/removed lines carry a sink token, so a large diff body never enters your context (SQL string-building has no clean regex → lean on the migration/query-path names from (1)). Any sensitive path → fire, record which repos trip (the *security review set* ⊆ changed-repo set). **Near-miss peek (bounded):** when (1) trips on the *name alone* with zero sink hits from (2) and the trip smells mechanical (rename, comment sweep, lockfile bump touching an auth-named path), you may take ONE look — `git -C <r> diff -- <file> | head -200` for the single tripped file — to downgrade an obviously-false trip instead of spawning a wasted security pass. Any real logic change in the peek, >200 lines, or any doubt → fire anyway (firing is cheap; a missed trigger isn't). Never peek more than one file per repo — two near-misses = fire. **Carve-out:** a first-party browser-storage round-trip is NOT a `deserialise` trigger unless the diff carries a dangerous sink or crosses a real trust boundary. Also fire on user request. (Reuse the changed-repo set from Test; recompute once only if review was skipped.)

- Firing: set `security_triggered=true`. **Normally Mode C rides the Review spawn (Mode B then C, opus)**; review gate-skipped → standalone `lead` security spawn. Multi-repo → surface fanout. Either shape direct-nests one `team-code-reviewer` per bucket when ≥2 buckets trip — no signal, synthesises in the same spawn. **Artifact check.** `fix-required` `high` → blocking: `cycles.review++` (>2 escalate), route to `engineer`, then **re-enter test targeted** (`re-validate targeted: <files>`; Impacted only) **→ review+security (one spawn)**. `medium`/`low` → **append to `FOLLOWUPS.md > Open` immediately** (`F-<run-id>-NN`, `security`, `path:line`), proceed to docs. Not firing → `security_triggered=false`.

### Ship Gate (pre-docs)

Inner loops (Test/Review/Security) run **Impacted** only; the full suite and existing project lint/type/static checks run **once per converged final diff, here**. Change Gate clean → run the **Full-suite** cmd plus the lint/static commands recorded in `tests.md > Commands` once via Bash, **failure-aware capture:** first run captures only the exit code + `tail -40` (`<cmd> 2>&1 | tail -40; echo "exit=${PIPESTATUS[0]}"`) — never the full green stdout in your context. **Red → re-capture wider once** (`<cmd> 2>&1 | tail -200`, or the runner's failure-summary flag if `tests.md > Commands` names one) so the diagnosis isn't starved by the 40-line window; still bounded, still no `qa` re-spawn = authoritative ship-blocking `passing`. Multi-repo → each surface-set repo.

- **Green** → set `Status: passing` and record `ship gate: green (<cmd>)` in `tests.md > Results` → docs.
- **Red** → regression Impacted missed: `cycles.test++` (≥3 escalate) → `engineer` → re-enter Test targeted (re-review changed repos only).
- **Skipped types** (chore/docs; spike) → no full suite → no gate.

No full-suite run occurs in inner cycles; a changed diff after a red gate must converge and pass a new Ship Gate.
