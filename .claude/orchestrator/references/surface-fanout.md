# Orchestrator reference — Surface (per-repo) fanout

> Loaded on demand by the main agent (`.claude/orchestrator.md`). The **third, orthogonal fanout axis**: split the read-and-judge phases — **review (step 11), security (step 12), test (step 13)** — one agent per changed repo on a **multi-repo control-plane run** (`state.repos` size > 1). Read this **only** when the run's changed-repo set is > 1; a single-repo run (the common case) never needs it. The shared dispatch mechanics live in `.claude/orchestrator/references/fanout.md > Surface (per-repo) fanout`; this file holds the per-step decisions and the non-primary-repo dead-ends that were inline in steps 11/12/13.

## Step 11 (review) — surface fanout decision

Otherwise: **Surface (per-repo) fanout — decide this FIRST, it is the outer loop around everything else in this step.** Compute the **changed-repo set**: the repos this run actually wrote to. **Take the engineer's returned per-repo changed-file list as the authoritative source** — it knows what it touched, and for `fix` (which commits test+fix and leaves a *clean tree*, so `git status` shows nothing) it is the *only* reliable signal. Confirm each candidate with `git -C <r> status --porcelain` non-empty OR new commits ahead of `<r>`'s base branch, and **restrict to repos in `state.repos`** (or `[repo_root]` when `repos` is `null`) so an unrelated sibling repo carrying stray local changes the run never touched is not pulled in. (Leaning on the engineer's report rather than a bare git scan is what closes both the `fix` clean-tree case and the stray-sibling case.)
    - **Set size ≤ 1 → single-repo path (unchanged).** Run the rest of this step exactly as written below against `repo_root` (or the one changed repo). This is the default and covers every non-control-plane run. If `state.repos` lists sibling repos but the engineer's authoritative changed-file report confirms only the primary `repo_root` changed, stay on this path — do not pay the surface coordinator cost just because sibling repos exist.
    - **Set size > 1 → surface fanout.** Spawn **ONE** foreground `lead` in its **Surface-coordinator variant** (`lead.md > Mode B > Surface-coordinator variant`), passing the changed-repo set. It **nests one `general-purpose` per-repo helper per repo itself** (the Per-repo variant contract inlined, `repo_root=<r>`, foreground, one message — review only that repo's diff against its slice of `plan.md`/`spec.md`, return a per-repo block), collects the blocks, and writes the single unified `review.md` in the **same spawn** — no separate synthesis re-spawn. Helpers are `general-purpose`, **not** `lead`, so the same-message batch clears guard Case 3; full rationale (and why this replaced the old `run_in_background` batch) lives in `## Fanout dispatch > Surface (per-repo) fanout > Dispatch`. **Cap 6** nested helpers; with >6 changed repos, group in ≤6. Each per-repo helper is **single-pass** — do NOT nest the 6-lens review fanout inside each (6×N agents); reserve lens-fanout for a single repo whose own diff is genuinely non-trivial, within the concurrency cap. The model-override + lens rules in the prose below apply **to each per-repo helper** (decide per repo from that repo's plan slice). **You** write `state.json` when the coordinator returns; resume is **fanout-granular, not per-repo** — a mid-fanout `--resume` re-runs the whole coordinator (review writes no production code, so re-reviewing is safe and cheap; no `review_repos_done` analog to `impl_phases_done`). The coordinator's unified `review.md` carries one `### Repo: <path>` subsection per repo under `## Per-repo review` plus the global anti-bias walk (each `spec.md` AC ticked against whichever repo's block implements it). **Aggregate verdict = `pass` iff every repo passes**; any repo `fix-required` makes the run `fix-required`. **`cycles.review` bumps once for the whole fanout, not per repo.** The verdict handling below (fix-required → engineer; ≥ 2 cycles → escalate) operates on the aggregate exactly as in the single-repo path. The coordinator keeps the high-stakes-model rule below (opus when any repo earned it).

## Step 11 — non-primary-repo blocking finding

    - **(Surface fanout) A blocking finding in a NON-primary repo has no auto-fix path this slice.** `engineer` (step 10) and ship (step 15) are scoped to the primary `repo_root`, so they can only remediate findings *in* `repo_root`. When the aggregate `fix-required` is driven by a finding in a repo ≠ `repo_root`, **do not route it to `engineer`** (it would edit the wrong repo) — surface it to the user via `AskUserQuestion` (fix manually in that repo, or accept/defer), and route only the `repo_root` findings to `engineer`. This is the live consequence of the single-`repo_root` boundary (`WORKFLOW.md > Multi-repo boundary`): parallel review can now *find* cross-repo problems faster than this slice can *fix* them.

## Step 12 (security) — surface fanout

      - **Surface (per-repo) fanout (same outer loop as steps 11/13).** Security-review set size > 1 → spawn **ONE** foreground `lead` in its **Surface-coordinator variant** (`lead.md > Mode C > Surface-coordinator variant`), passing the tripping-repo set; it **nests one `general-purpose` per-repo helper per tripping repo** (Per-repo Mode C contract inlined, `repo_root=<r>`, foreground, one message — return a per-repo block) and writes the unified `security.md` (one `### Repo: <path>` subsection each) in the **same spawn** — no synthesis re-spawn. Helpers are `general-purpose`, not `lead`, to clear guard Case 3 (rationale: `## Fanout dispatch > Surface (per-repo) fanout > Dispatch`). Each per-repo helper stays single-pass — do NOT nest the per-bucket fanout inside each. **Cap 6**, group beyond. Set size ≤ 1 → single-pass below.

## Step 12 — non-primary-repo high finding

      - **(Surface fanout) A `high` finding in a NON-primary repo can't be auto-fixed this slice** — `engineer` is scoped to the primary `repo_root` (same boundary as steps 11/13 / `WORKFLOW.md > Multi-repo boundary`). Surface it to the user via `AskUserQuestion` (fix manually in that repo, or accept the risk) instead of routing to `engineer`; route only `repo_root` high findings to `engineer`. A `high` you can't auto-fix is still blocking — never downgrade it to fit the boundary.

## Step 13 (test) — surface fanout

      - **Surface (per-repo) fanout — decide first (same outer loop as step 11).** Compute the changed-repo set the same way as step 11 — the engineer's reported per-repo changed files (authoritative, and the only reliable signal for `fix`'s clean tree), confirmed by git, restricted to `state.repos` (else `[repo_root]`). **Set size > 1 → surface fanout**: spawn **ONE** foreground `qa` in its **Surface-coordinator variant** (`qa.md > Mode: Execute > Surface-coordinator variant`), passing the changed-repo set; it **nests one `general-purpose` per-repo helper per repo itself** (Per-repo variant contract inlined, `repo_root=<r>`, foreground, one message — run that repo's suite over its slice of `test-plan.md`, return a per-repo result block) and writes the unified `tests.md` (one `### Repo: <path>` subsection per repo under `## Per-repo results`, plus the global AC-coverage walk mapping each `spec.md` AC to whichever repo's tests prove it) in the **same spawn** — no synthesis re-spawn. Helpers are `general-purpose`, not `qa`, to clear guard Case 3 (rationale: `## Fanout dispatch > Surface (per-repo) fanout > Dispatch`). **Cap 6**, group beyond. Each per-repo helper stays single-pass (don't nest the test-category fanout per repo). **You** write `state.json` when the coordinator returns; resume is **fanout-granular** — re-run the whole coordinator (tests are idempotent to re-run; no per-repo done-tracking). **Aggregate status = `passing` iff every repo passes**; any repo `failing` makes the run `failing`. **`cycles.test` bumps once for the whole fanout, not per repo.** The cycle/coverage/edge-gap handling below operates on the aggregate. For `fix`, the regression contract lives in the one repo that holds the bug — only that repo's per-repo helper runs the pre-fix verification. **Set size ≤ 1 → single-repo path (unchanged):** continue below against `repo_root`.

## Step 13 — non-primary-repo failing test

      - **(Surface fanout) A failing test in a NON-primary repo can't be auto-fixed this slice** — `engineer` is scoped to the primary `repo_root` (same boundary as step 11 / `WORKFLOW.md > Multi-repo boundary`). When the aggregate `failing` is driven by a repo ≠ `repo_root`, surface it to the user via `AskUserQuestion` (fix manually in that repo, or accept/defer) instead of routing to `engineer`; route only `repo_root` failures to `engineer`.

## Step 13 — visual verification in multi-repo fanout

**In surface (multi-repo) fanout**, restate the visual instruction in each per-repo qa prompt whose repo's diff touches UI; the coordinator carries per-repo visual findings + deferrals up (`qa.md > Surface-coordinator variant`), and you run this backstop for any repo that deferred.
