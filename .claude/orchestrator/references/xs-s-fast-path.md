# Orchestrator reference — Fast path (XS/S/M)

> Loaded on demand by the main agent (`.claude/orchestrator.md`). The `## Size-aware execution` section keeps the size picker, **Never shrinks**, **Patch lane (XS subtype)**, and the size/field upgrade rules inline; this holds the fast-path deltas. Read it when `size` ∈ {XS, S, M}. Everything not listed here runs as written in the main flow; **M-scoped deltas are only where marked M** — the rest of this file is XS/S. Kept terse on purpose: it stays resident for every turn of the run.

- **XS reads THIS file and nothing else (Phase 1).** At `size=XS`, after `orchestrator.md` this file is the **only** orchestrator reference you open from the interview through the gate: do **not** read `interview.md`, `phase-1.md`, `gate.md` or `size-execution.md` — their XS-scoped content is folded in below, and `orchestrator.md > Size-aware execution` already carries the picker, the never-shrink set and the upgrade rules. (Measured: **44% of an XS run's wall clock happens before its first `state.json` write** — ~64 KB of playbook across ~7 sequential reads, to produce a 1.8 KB `run.md`. Boot is the largest single block in the lane, larger than Design, Build, Review or Ship individually.) S and M read the full chain; anything that escalates the run past XS restores it by definition.
  - **Interview (XS, folded).** Requirements digest from the conversation → estimate `size` + classify `field` → the three detections → the one question batch below. Under `--yes` no question is asked: fill each slot from the intent or its `(Recommended)` default in the same turn.
  - **Artifact checks (XS, folded — run against `run.md`).** Contract core present (`## Goal` · `**Type**:` · ≥1 `AC#` · ≥1 `T###` with a `verify:`); every acceptance criterion carries exactly one `AC#`; every `T###` carries an `[AC#]` tag; no `[NEEDS CLARIFICATION]`; (feat/fix/refactor) every `AC#` has a `## Coverage` row. Fail → fix it yourself and re-check; a failure you cannot fix inline is `SIZE_UPGRADE: S`. INDEX → `planned`.
  - **Gate (XS, folded — never shrinks).** Print the tight summary: goal + `Type` + `Ship as`; ship disposition (`commit on ship` asked every run, default `no`; PR only if commit=yes); **the acceptance scenarios as the contract, one line each — "done when each is true; confirm each line, or correct it"** (per-line confirmation is the only user-validated link from spec to code and is never dropped); `Assumptions (inferred)` if any; the phase plan with any `(deviates from matrix)` row called out for its own confirmation; test plan coverage + `e2e_visual` (default `off`). Then ONE `AskUserQuestion`: Q1 `approve | revise`, Q2 `commit on ship?`, Q3 only if the plan carries deviations. Options are `approve | skip <n> | run <n> | commit on|off | e2e on|off | revise <notes>`; `skip`/`run` are discretionary-only (Test/Review/Docs) and refuse the protected set. It **loops until `approve`**; free-form = `revise` for this run. `revise` → targeted edit of `run.md`, never a regeneration. Under `--yes` → auto-satisfy `approve` only when no `BLOCKER:` is open and every deviation is verification-neutral (`orchestrator.md > Non-interactive` is canonical); resolve nulls to defaults and record the note. On `approve`: INDEX → `approved`, state `step=gate, next_step=implement`.
- **Spend round-trips like money (XS/S).** Every tool call re-sends the whole accumulated context, and this lane's cost is round-trips × that context. Read what a step needs in as few calls as possible, prefer one compound `git` command over two, read a template only when about to fill it, never re-read what is already in front of you. Not a licence to skip the `state.json` re-read or any check. **Then send boot as ONE message** — the reads this lane needs before it can ask anything (`.workflow/INDEX.md`, `.workflow/FOLLOWUPS.md`, `.workflow/CONTEXT.md` when present, the repo-detection `find`) do not depend on each other's content, so on a host that runs calls concurrently they cost one round-trip instead of four. Boot is this lane's largest block and it is made of sequential round-trips, not of work. Never batch a speculative read, and never batch a state write with the spawn it gates. Canonical rule: `orchestrator.md > State discipline > Efficiency`.
- **Read the repo ledger before you walk (XS/S).** `.workflow/CONTEXT.md` exists → read it **once, before the first grep or LSP call** of the current-state walk (and before Test derives its baseline). It is the accrued `path#anchor — fact` map of what prior runs established in this repo — entry points, callers, invariants, test runner/fixtures — grouped by area, so a fact it already carries costs one read here instead of a walk. Then walk only what it doesn't cover. **Evidence, not authority**: spot-check load-bearing claims by re-resolving a sample of anchors, code beats the ledger, and post-Implement the diff beats both. Absent, or a claim that won't re-resolve → walk it yourself. This lane cold-walked by design before; it no longer does. Canonical rule: `orchestrator.md > Size-aware execution`.
- **One question batch (XS/S).** Fold setup + interview into one `AskUserQuestion` (≤4, catch-all last). (M keeps the split setup + interview batches — size matrix.) Over 4 → drop the type question (record as `Assumptions (inferred)`), then branch (propose in intro); never drop an interview slot or the catch-all. Checkout right after. **Say the path** in the status line + gate summary (e.g. "Size: XS → fast path: combined spec+plan, merged docs+ship, inline retro").
- **Under `--yes`, the XS/S interview is a digest, not a deliberation.** No question can be asked, so fill every slot from the intent or its `(Recommended)` default in the SAME turn as the size/field call — don't spend turns weighing options you cannot ask about. Detections and digest still run; a load-bearing slot with no safe default still stops `NON_INTERACTIVE_BLOCKER:`. (Cost 81s when it deliberated at XS.)
- **XS designs inline — no spawn at all.** You write `run.md` yourself from `_templates/run.md`: you already hold the digest, the intent and the ACs, and at ≤3 ACs on a hermetic unit there is no design space for a second opinion to explore. Run the same artifact checks + pre-gate scan against it, and self-review before the gate (contract core present, one `AC#` per criterion, a `verify:` per task). Escalate to the cold `lead` spawn the moment the unit stops being hermetic — a caller to stay compatible with, persisted data, a trust boundary — which is `SIZE_UPGRADE: S` anyway. (Design was 169s / 56% of a run as a spawn, to fill a 39-line template; the `lead` brief alone carries a 21 KB reference.)
- **S designs inline too — same four artifacts, written by you.** At `size=S` you write `spec.md` + `plan.md` + `tasks.md` + (feat/fix/refactor) `test-plan.md` yourself, following `.claude/agents/references/lead.md > Combined variant` steps 1–5 as if they were addressed to you, then run the artifact checks + pre-gate scan. **Nothing about the artifacts changes — same sections, same depth, same reference access.** The only thing that moves is *who holds the pen*: you already carry the digest, the intent, the Q&A and the size/field call, so a cold `lead` spawn re-reads a 29 KB brief (`lead.md` + `references/lead.md`) and re-derives what you just decided. Measured on brownfield-S: Design was **9–10 min of a 20–23 min run (39–49%)**, the largest phase in every run of the baseline. **This is not the thing that failed at S** — what failed, and was rejected by the ratchet at 9/pass → 8/fail, was *rationing* the design (capping artifact length, restricting which reference sections may be read); that stays forbidden, and the paragraph below still governs. **Escalate to the cold `lead` spawn** — don't improvise — the moment the walk turns up a risk flag the size call missed (persisted data beyond the run's own store, a schema, a public API/event contract, a trust boundary, cross-repo coupling) or the scope proves bigger, which is `SIZE_UPGRADE: M` and restores the full machinery by definition. Phase 1 is then **warm**, so Implement continues inline in main (`phase-2.md` op 5) — Review+Security and Docs+Ship stay cold spawns.
- **S spawn budget: 2** — Review+Security (cold on purpose: S is the tier *defined* by having a caller to stay compatible with, so the diff gets eyes that did not write the plan — `WORKFLOW.md > Anti-bias rule`) and Docs+Ship. Design, Gate, Implement, Test and Retro run inline. A third spawn means an escalation happened; `SIZE_UPGRADE` is the only sanctioned way to it. Check `dev-metrics.sh > spawn_seen`, not `state.json > spawn_count`. (Trimming main's resident Phase-2 references at XS/S was tried in the same rejected pass and is **not** adopted — the XS-lane precedent for resident trimming does not transfer to a lane whose main context already holds Design and Implement.)
- **Spec+plan+tasks+test-plan in one spawn (M).** Skip `pm`; spawn `lead` combined mode (`.claude/agents/references/lead.md > Combined variant`) with digest + Q&A; the spec/plan/tasks/test-plan checks run on the returned artifacts. **Do not ration the design.** Capping artifact length or restricting which reference sections `lead` may read was tried, cost more, and dropped quality — rejected. The `run.md` ≤ 40-line budget works at XS precisely because a hermetic unit with ≤3 stated ACs has no design space; S and up do, and starving it costs more than it saves — which is why the S inline path above moves the author and not one line of the contract. **M:** model **opus** (spec quality rides the plan spawn); brownfield M builds `context.md` FIRST (Design's Context sub-step — integration points from the digest) and passes it; plan sections at full Mode A depth per plan `Size`. **Clean-tree check after return:** `git -C <repo_root> status --porcelain` — any source change means lead implemented early; revert, note, proceed. Test plan folds in (feat/fix/refactor; gate surfaces it, pre-gate scan still checks each AC has a Coverage-plan row; chore/docs/spike → append `test-plan` to `skipped_steps`). Handle return first line (`SIZE_UPGRADE`/`FIELD_UPGRADE`/`BLOCKER`).
- **XS micro-lane artifact: one `run.md`.** At `size=XS` the design step writes `.workflow/<id>/run.md` (`_templates/run.md`) INSTEAD of the four files — same contract core (Goal · `**Type**:` · `AC#` · `T###`+`verify:` · Coverage lines), one artifact. The artifact checks + pre-gate scan run against `run.md`; state cursor names are unchanged (the combined write still records `step=plan|test-plan`, `next_step=gate`); Test-inline reads its `## Coverage` Impacted cmd. `SIZE_UPGRADE: S` → the re-spawn emits the full four-artifact set (`run.md` stands as digest input; delete it after the fold). S and M keep the four files.
- **`run.md` ≤ 40 lines.** Contract core only — no alternatives, risk register, or rationale prose; at ≤3 ACs on a hermetic unit there is nothing to weigh, and every line is re-read by Implement, Review and Retro. (Plan reached 227s / 41% of a run without this.)
- **Test inline** (feat/fix/refactor, `e2e_visual=off`): the engineer implemented the planned tests (engineer Mode A rule); run the **Impacted** cmd from `test-plan.md > Commands` via Bash yourself and write `tests.md` from the template — one row per Coverage-plan AC + result, Commands, (fix) the pre-fix-fail evidence from the engineer's two-commit sequence. Failing → route to `engineer` (`cycles.test++`, limit 3, unchanged). `e2e_visual=on` → spawn `qa` as usual.
- **Review inline at XS** with no risk flag (persisted data / schema / API contract / security path / cross-repo coupling / migration): read the diff against `run.md`'s `AC#` and `## Coverage` rows, write `review.md` from the template. **Any** finding, or a fired security trigger, escalates to the real `lead` review+security spawn — the cheap path is for when there is nothing to say, not a licence to say nothing. The security-trigger scan itself ALWAYS runs (never-shrink). **S and M keep the cold review spawn.**
- **Fanout XS/S-scoped** — `lead` attempting to direct-nest review helpers on XS/S is itself evidence of a size-upgrade; return `SIZE_UPGRADE:` instead. (M: the size matrix governs — core 3-lens review fanout allowed when justified.) **Docs+ship in one spawn** (Mode B then C) at **S/M**. **At XS both run inline** — docs are a README/JSDoc touch, ship is `git add` plus the ready-to-run commit command (`commit_on_ship` defaults `no`); neither waives a check. Anything larger — a new doc page, a real commit, a PR — spawns `engineer` Mode B/C as usual. **Inlining these at S is measured and REJECTED, twice** on two different shapes — cost regressed and quality spread widened both times: **S keeps the docs+ship spawn.** The plausible reason is the same one the XS lane found — inlining *relocates* work into a main context that is already carrying Design and Implement, and at S that context is no longer small.
- **XS loads no skill body.** The router in `rules/fundamentals.md` is the whole pre-flight — no `SKILL.md`, no `references/<file>`. A friction that genuinely needs one means the run is not XS: return `SIZE_UPGRADE: S — <friction>`.
- **XS spawn budget: 0** — Design, Gate, Implement, Test, Review, Docs, Ship and Retro all run inline. Any spawn means an escalation happened, and `SIZE_UPGRADE` is the only sanctioned way (it changes the tier, so the budget moves with it). Check `dev-metrics.sh > spawn_seen`, not `state.json > spawn_count` — the latter is self-reported and has read 0 on a run that demonstrably spawned.
- **Skipped-test stub inline** for chore/docs (write `tests.md > Skipped` yourself). **Close: XS/S inline.** Stamp `done_at` first, update INDEX/FOLLOWUPS. **At XS write no `retro.md`**: Close runs after Ship so it cannot change the delivered code, and a retrospective document for a one-line fix is 22% of the run's stamped wall clock that nobody reopens (`WORKFLOW.md > Retro at XS`). S and up still write `retro.md`. Skill round only if something surfaced.

**Why the XS lane is this thin.** An XS run costs ≈ `resident playbook × turns`, not `spawns` — cutting spawns barely moves it, because inlining *relocates* work rather than removing it. So at XS the only lever that pays is loading less and taking fewer turns, and the honest first question is whether the run needs `/dev` at all (`orchestrator.md > Size-aware execution > XS value check`).

**Why S inlines Design.** Design is the largest phase of a brownfield-S run — a cold worker re-reading the brief to re-derive a size, field and intent the orchestrator had already settled — so it moves inline. Review is second and **keeps its spawn**: the plan's author reading their own diff is the bias the `WORKFLOW.md` anti-bias rule exists to break, and that independence is worth its minutes. Inlining relocates rather than removes, so expect wall to move further than cost.
