# Orchestrator reference — Resume

> Loaded on demand by the main agent (`.claude/orchestrator.md`). Open this only when invoked as `/dev --resume <id>`. A fresh run never needs it.

### Resume (`/dev --resume <id>`)

1. Read `.workflow/<id>/state.json`.
2. If `repo_root` is set: run `git -C <repo_root> checkout <branch>`. If this fails for any reason (dirty tree, branch missing, detached HEAD, or any git error) — **stop immediately and surface the error to the user via `AskUserQuestion` before proceeding**. Never continue a resume on an incorrect or unverified branch.
3. Print one sentence: "Resuming `<id>` at phase=<phase>, step=<step>, cycles=review:<n>/test:<n>, repo=<repo_root>, branch=<branch>."
4. Jump to the matching step below. Don't replay completed steps. **Team-built run reconciliation:** if `.workflow/<id>/` holds Phase-1 shards (`state.plan.json` / `state.test-plan.json` / `state.uxui.json`), the run's Phase 1 was driven by team-mode commands that advanced their shards, not the `state.json` cursor — so a stale `step` of `spec`/`plan` here does **not** mean that work is undone. Route to the **gate (step 9)** (whose first action folds the shards and reconciles the cursor), and don't replay a `plan`/`test-plan` step whose artifact (`plan.md` / `test-plan.md`) already exists. A `step` of `test-plan` maps to **step 8a** (re-run the test-plan check, then proceed to the gate). A `step` of `revise-spec`, `revise-plan`, or `revise-test-plan` maps to the **gate (step 9)** — re-present the in-progress spec/plan/test-plan for confirmation rather than looking for a numbered `revise` step. **When the matching step is step 10 (`step=implement`), read step 10's `Resume guard` bullet BEFORE acting on the step's "Spawn `engineer` in implement mode" heading** — a mid-fanout resume (non-empty `impl_phases_done`) must route to the Integration variant, not re-dispatch every phase. If `state.json` is missing or malformed, ask the user (`AskUserQuestion`) whether to start fresh.
5. **Legacy / missing `size` → treat as M/L (full machinery).** A run created before size-aware execution existed has no `size` field. Never infer a fast path on resume — a missing or `null` `size` means run every remaining step with the full M/L machinery (separate `pm`/`lead` spawns, separate docs/ship/retro). Over-provisioning a resumed run is safe; silently fast-pathing one that was planned under the full flow is not. Backfill `size` in `state.json` only if you can derive it from the already-written `plan.md > Size`; otherwise leave it null and stay on the full path. **Missing `field` goes the *other* way — leave it null (which the step-13½ guard reads as not-brownfield, so it skips improve).** A pre-`field` legacy run was planned without phase 7½; adding a new phase to an in-flight run is the unsafe direction (unlike size, where *more* machinery is the safe default), so a null `field` correctly skips improve rather than back-filling brownfield. Backfill `field` only from an already-written `plan.md > Field`.
